# 结题开发实施计划

编制日期：2026-10-27。依据上级目录申报书和《校创结题差距与验收清单》，保留原申报目标，不将工程完成等同于学校验收通过。

## 开发顺序与分工

1. 核对要求、现有实现和接口，确认技术变更、模型准备及真实验收材料。
2. 并行开发：媒体底层负责公式与音频的本地识别、校对记录、确认后的特征融合和持久化；媒体界面负责后台任务、原始结果、草稿、应用、取消与重试；导出模块负责按体系隔离、维度完整性、识别记录与归档索引。
3. 主 agent 负责接口集成、无依据维度检查、独立评测工具、冻结程序的工作进程入口、发布构建和回归验证。
4. 汇总可复现结果，更新用户手册、开发说明和验收矩阵，形成源代码与可生成的实际发布产物。

## 并行文件边界

| 工作线 | 写入范围 |
|---|---|
| 媒体底层 | `app/core/models.py`、公式/音频预处理、新增媒体识别与校对服务、相应专项测试 |
| 媒体界面 | `app/ui/pages/page_import.py`、新增媒体校对对话框、相应界面测试 |
| 导出完整性 | `app/core/dataio/exporter.py`、`app/ui/pages/page_export.py`、新增导出回归测试 |

## 共同接口与约束

公式和音频分别保存校对记录；原始识别、用户草稿和确认结果分开。只有明确确认的内容参与自动分类。识别失败或取消不得覆盖题干、历史确认结果或现有分类。修改确认内容后作废旧分类。模型在运行期只读取本地文件，准备阶段下载与离线运行分开。

## 验收与交付门槛

- 保留旧题库和旧备份的兼容性；专项测试和已有完整测试均需执行。
- 检验保存、重启、导出及备份恢复后的识别与校对记录一致性。
- 两套同学科且维度不同的体系导出不得混入其他体系或静默缺列。
- 发布包需实际构建和本机冒烟验证；干净 Windows、macOS、低配硬件分别标记是否实测。
- 独立真实数据记录来源、标注、集合隔离、识别失败和完整自动处理耗时。内置样例和模拟引擎测试不能替代真实媒体验收。
- 保留原全流程 1 秒、提升 5% 等指标；未达标如实记录，不改变统计口径制造通过。
- 真实学生试用、导师确认、公开仓库与学校结题审批需要外部真实行为和材料，未发生不得标记完成。
