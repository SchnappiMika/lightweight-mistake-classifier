# 印刷图片识别与校对验收记录

更新日期：2026-10-27。当前交付范围是印刷中文、英文及选项的文字提取、人工校对、应用题干与后续分类归档。复杂公式 LaTeX、手写识别、图形关系理解及听力转写仍未完成。

## 安装与模型来源

Windows 下双击项目内 `安装图片识别.bat`。脚本复用现有启动检查，在项目 `.venv` 安装 `requirements-ocr.txt`，校验模型并对一张真实栅格图片执行独立进程识别自测，不会打开或修改用户错题。若已安装组件的模型缺失或损坏，会联网重新安装固定版本组件以修复模型，然后再次自测。

| 项目 | 本次验证配置 |
|---|---|
| 系统与 Python | Windows，本机 Python 3.13.5；当前 OCR 固定版本要求 Python 3.11 或以上 |
| OCR | RapidOCR 3.10.0 |
| 推理运行时 | ONNX Runtime 1.31.1，CPU，单次推理内线程 2、并行线程 1 |
| 检测模型 | PP-OCRv6_det_small.onnx，9,929,594 字节 |
| 方向分类模型 | ch_ppocr_mobile_v2.0_cls_mobile.onnx，585,532 字节 |
| 识别模型 | PP-OCRv6_rec_small.onnx，21,234,383 字节 |
| 模型合计 | 31,749,509 字节，约 30.3 MiB；运行库和其他依赖另计 |
| 模型位置 | `.venv/Lib/site-packages/rapidocr/models`，随固定版本 wheel 安装 |

程序明确指定上述三个模型的本地路径，实际识别前检查大小和 SHA-256，缺失或损坏时提示修复。环境自检只检查组件可发现性及文件存在、大小，不加载模型或下载。完整校验值保存在 `app/core/preprocess/image_ocr.py`。

首次安装需要联网。识别进程禁止 Python socket 建立网络连接，不接收远程图片地址。已在禁止连接的冷启动进程中完成模型加载和图片识别；这不等于对所有旧识别适配器或整个系统实施了操作系统级断网测试。

## 可操作流程

1. 导入图片，选中题目和学科，打开“图片文字：识别与校对”。
2. 点击“开始识别 / 重试”，对照可缩放原图编辑结果。原始识别和逐行模型分数单独保留，分数明确标注不是准确率。
3. 保存草稿不会改变已有题干、特征或分类；只有明确“应用为题干”才替换文本并清除旧分类。已有题干不同时先要求确认。
4. 关闭窗口再分类，分类只使用已保存的题干和标注，不重复运行旧 OCR 追加未经校对的文字。
5. Excel 导出使用已应用的题干，新增图片识别状态。题目存储和备份保留原始识别、草稿、分数、位置框、附件内容哈希、耗时及应用状态。恢复后附件重新定位，内容哈希仍可核对。

草稿和题干不同会显示待重新应用，题干另行编辑不会覆盖校对草稿。重新识别成功才更新识别记录；取消或失败保留已有内容。附件变化或丢失时拒绝应用旧识别结果，避免把旧图文字用到新图上。

## 故障处理与界面验证

- 本机实际发现 Qt 初始化后，在同一进程导入 ONNX Runtime 会发生原生访问冲突，普通 Python 异常处理无法拦截。界面现使用独立识别进程，Qt 和推理运行库分开加载；识别在后台等待，运行库异常退出可转成界面错误。每次任务结束后释放模型，下次重新加载。
- 识别时锁定其他数据任务，校对窗口保持可响应；可取消当前结果，等待计算完成后返回。当前进程超时上限为三分钟；超时结束子进程并提示缩小图片。
- 原图预览默认适应宽度，可选择 50%、100%、150%、200%，支持滚动。已核对 Windows 原生渲染的常用尺寸和 760×520 最小尺寸，主要文字和控件可见。
- 识别和保存失败都保留原有题干与分类；保存失败的编辑内容继续留在校对框。关闭未保存草稿时支持保存、放弃和取消关闭；任务运行中禁止关闭窗口。
- 空白、损坏、丢失及超过 30 MiB 或 2500 万像素的图片会报告错误；不会以空识别内容宣告成功。

| 验证 | 本次结果 |

| 原生界面完整流程 | 从四行高数印刷图片识别，人工补充并应用，分类为“定积分及其应用”；保存后重载、Excel 导出、备份恢复和图片内容检查通过 |
| 失败处理 | 真实空白图明确拒绝；自动化测试另覆盖损坏图、缺图、超限、保存失败、附件变化、取消、未保存关闭、进程异常与超时 |
| 软件回归 | 具体最新数量和耗时见 `开发进度与验收.md` |

项目内 `.startup-check/ocr-real` 保留本次生成的图片、校对窗口截图、识别记录、完整流程脚本、Excel 与备份 ZIP。复现时可运行：

```powershell
.venv/Scripts/python.exe tools/check_image_ocr.py
.venv/Scripts/python.exe .startup-check/ocr-real/verify_workflow.py
```

第二个脚本只在项目 `.startup-check/ocr-real/ui-workspace` 操作，会产生测试错题；该目录是本机验收产物，不属于发布依赖。首个检查脚本只识别临时生成的英文印刷图片。

以上图片是程序生成的清晰印刷栅格图，确实经过图片解码、模型检测和识别，没有拿预填题干冒充 OCR；但它们不能代表真实拍照、倾斜、阴影、密集排版或未见题目的准确率。尚未收集用户独立真实图片样本，也未完成干净电脑验收。耗时仅为本机样本记录，完整流程 JSON 另记录从点击识别到结果返回的等待时间，不用纯文本分类耗时代替媒体耗时。
