## 0 文档定位、口径与填写规则

### 0.1 这份文件解决什么问题

团队目前只有一台 Windows 电脑，没有干净 Windows 机器、没有 Mac、没有低配机。这意味着"外部验证"不可能靠现有设备"顺手测一下"完成，只能靠**可执行的任务单 + 统一的记录表 + 如实标注未验证项**来产生可归档证据。本文件给出这套东西；它不提供结论，只提供产生结论的方法。

本文件同时是四份材料的母版：

1. 发给同学的《试用任务单》（第 2 节，可直接打印）；
2. 组织者用的《观察记录表》《问题登记表》（第 3 节）；
3. 打印发放的《试用反馈问卷》（第 4 节）；
4. 设备验证用的《干净 Windows 清单》《低配与 macOS 清单》（第 5、6 节）。

### 0.2 事实与口径：哪些能写"已验证"

结题材料里凡出现"已验证/已通过/已实测"，只能引用下表左列已有事实卡支撑的项。右列一律不得写成已验证。

| 项目 | 当前状态（只按事实卡） |
|---|---|
| 软件版本与环境 | 1.0.0；Windows 11 + Python 3.13.5 主环境 |
| 发布形态 | 目录版，需整体保留目录，双击 `错题自动分类.exe` |
| 内置内容 | 5 套学科体系与示例题目（155 条），可离线运行 |
| 文本主流程 | 自动化回归 826 项通过；主验收（155 条人工标注样本）知识点准确率 98.1%、纯文本 98.8% |
| 媒体耗时（本机发布包冒烟） | 图片识别约 3 秒；31.88 秒音频转写约 12 秒；公式识别约 19 秒 |
| 公式能力边界 | 整页多公式混排不可靠，须裁剪单公式并对照原图校对 |
| 干净无 Python 的 Windows | **尚未完成** |
| macOS | **尚未完成**（需在对应系统构建与实测） |
| i5-8250U / 8GB 低配 | **尚未完成** |
| 真实同学试用 | **尚未发生**（即本文件要推动的事） |

另有一条容易被误用的口径：`发布包冒烟记录.json` 里的自动确认只验证数据链路，不等于人工核对准确；隔离性能记录里的文本热态毫秒数只代表纯文本算法，不代表含识别的完整流程，也不代表低配界面表现。引用这些数字时必须连同边界一起写。

### 0.3 编号、代号与归档规则

- 试用编号：`T-YYYYMMDD-Pn`，YYYYMMDD 换成当天实际日期（占位写法 `T-____-P1`）。日期当天填，不得预填或倒填；本文不提供任何示例日期，以免被误抄成真实记录。
- 试用者代号：P1、P2、P3……记录表只写代号与"专业+年级"，不写姓名、学号、手机号。姓名与代号的对应表单独一张纸，由组织者保管，不进结题材料。
- 问题编号：`ISS-001` 起顺序编号，全项目唯一，跨轮次不重号。
- 截图编号：`S-P1-03`（试用者代号-顺序号），文件命名为 `S-P1-03_分类页报错.png`，与记录表"截图编号"列一一对应。
- 证据目录：`evidence/trial/YYYYMMDD/` 下按 `P1/`、`P2/` 分开放截图、导出的 xlsx、备份 ZIP 的截图（ZIP 本体不必归档，记录大小与位置即可）。
- 只写真发生的：不补日期、不补人数、不补引语、不把"我以为他会卡在这里"写成"同学卡在这里"。

### 0.4 打印建议

第 2、4 节单独打印发给同学（A4 纵向，任务单每人 1 份）；第 3 节组织者自用（A4 横向，宽表）；第 5、6 节打印 1 份，由执行验证的人在机器旁勾选。

## 1 试用总体安排

### 1.1 目标

用 3–5 名非开发者的在校同学，各自在**自己的题目**上独立完成"启动→导入→分类→修正→重启→导出"，收集真实卡点与意见，形成"问题—修复—复测"闭环，产出可归档的《真实试用与迭代记录》，使申报书预期成果 3 有据可查。

明确不做的事：本次试用**不承担**分类准确率评测（准确率已有 155 条人工标注样本的主验收；试用问卷里的"是否符合预期"是主观感受，不能换算成准确率），也**不承担**性能指标验收（性能走第 5、6 节的设备验证）。

### 1.2 对象与人数建议

| 项目 | 建议 | 说明 |
|---|---|---|
| 人数 | 3–5 人起步，第二轮再补 2–3 人 | 3–5 人是执行建议，不是学校规定人数；材料中不得写成"按学校要求" |
| 身份 | 非开发者、非本项目组成员 | 开发者和项目组成员的自测只能算内部测试 |
| 专业覆盖 | 至少覆盖高等数学、大学物理、大学英语三个场景 | 一人可覆盖多场景，但同一场景至少有 1 名真实使用者 |
| 年级 | 大一至大三为主 | 与"日常有错题整理需求"的实际人群一致 |
| 设备 | 同学自己的 Windows 电脑优先 | 用同学自己的机器，才可能暴露"换机能不能跑"的真实问题 |
| 前置 | 未看过本软件演示、未参与开发 | 看过演示的人不再具备"第一次使用"的观察价值 |

人数不足时的处理：只有 2 人就不要在材料里写"覆盖三个专业"；照实写"2 人，覆盖高数与英语，物理场景未覆盖"，并说明补测计划。宁缺不造。

### 1.6 公平性要求（硬性）

1. **不替同学操作。** 键盘鼠标必须在同学手里。组织者代点一次，这份记录就只能算"内部测试"。
2. **不引导答案。** 不说"这里应该选高数""这个结果明显不对""点右上角那个"。同学问"对不对"时，回答"按你自己的判断填"。
3. **不预告坑。** 不提前讲解"要先选同学科体系才生效""修正会自动保存"。这些正是要观察的。
4. **允许失败并如实记录。** 任务没做完不是失败的材料，是真实的材料。写完"未完成"再写卡点，比硬凑"完成"有用。
5. **不催、不暗示时间压力。** 只在超时过多时提醒"可以停下记录当前卡点"，不替他把流程走完。
6. **不筛选反馈。** 负面意见原话照录（去标识），不改成"建议进一步优化"。
7. **同版本对比。** 第二轮换版本时必须记录版本号，不能把两个版本的记录混成一份"试用结果"。

## 2 试用任务单（发给同学，照着做）

> **给同学的话**：这不是考试，做不出来也是有用的结果。每一步做完在"□"里打勾；做不下去就在记录表写"卡在哪一步、屏幕上写了什么"，然后叫组织者，不要自己反复试超过 2 次。全程用自己的题目，不要用组织者给的答案。

### 2.0 通用说明

- 软件是**目录版**：整个文件夹要一起保留，只复制 `错题自动分类.exe` 无法运行。
- 你录入的题目保存在本机用户目录 `.mistake_classifier` 里，不上传。
- **不要点**"清空全部""删除选中""恢复内置体系"；不要用 `--reset` 参数。
- 三种任务难度递增：任务 A 必做，任务 B 必做，任务 C 选做（组织者会说明素材是否准备好）。
- 计时从"点下按钮"到"界面恢复可操作"，用手机秒表，记整秒即可。
- 遇到报错，先截图（`Win + Shift + S`），再抄文字。

### 2.1 任务 A：基础文本流程（必须完成）

**前置条件**

- 一台能正常开机的 Windows 10/11 电脑；发布目录已解压好。
- 已拿到本任务单与观察记录表；已记下软件版本号 `1.0.0`。
- 组织者已确认这台机器此前没有本软件的题目数据（或已记录初始题目条数）。

**逐步操作**

| # | 做什么 | 看什么/记什么 |
|---|---|---|
| A1 | 双击 `错题自动分类.exe` | 从双击到主界面可点击的秒数；是否弹出任何窗口 |
| A2 | 左侧五个入口各点开一次，每页停 10 秒，只看不操作：导入与预览 → 分类体系管理 → 一键分类与修正 → 反馈与增量优化 → 导出与归档 | 哪一页第一眼不知道是干什么的 |
| A3 | 回到"导入与预览"，看列表上方的题目总数 | 记下初始条数（可能是 0） |
| A4 | 二选一导入：① 点"载入示例错题"（载入 155 条内置示例）；② 点"一键导入 TXT"，选组织者准备的 5 条 txt | 导入是否一次成功；有无报错；列表条数变化；导入后点一条看"学科"显示什么（TXT 会沿用当前筛选的学科，空时显示"通用"——这是观察点，记下实际值，不要替同学改） |
| A5 | 进"分类体系管理"，确认五套内置体系（高等数学、大学物理、大学英语、线性代数、概率论与数理统计）都在 | 能否看懂"体系/维度/标签"的关系 |
| A6 | 进"一键分类与修正"，顶部选择与题目学科一致的体系，点"一键分类" | 分类耗时；结果条数；界面是否卡住 |
| A7 | 在左侧列表选 1 条你认为判错的题（若都对，选 1 条你熟悉的题核对依据） | 右侧"分类结果与依据"里的标签、粗筛命中词、置信度是否看得懂 |
| A8 | 右侧"修正操作"里把该维度改成你认为正确的标签 | 改完列表里的结果是否立刻变；有没有"保存"按钮 |
| A9 | 关闭软件（右上角 ×）。若有"任务未结束"提示，等结束后再关 | 关闭是否顺利；有无报错 |
| A10 | 重新双击 `错题自动分类.exe`，找到 A7 那条题 | 修正后的标签是否还在（这是"会不会丢数据"的关键） |
| A11 | 进"导出与归档"，看"导出结构预览"，点"一键导出 Excel" | 预览里说会生成哪些 sheet；导出耗时；有无报错 |
| A12 | 点"打开输出目录"，打开刚生成的 xlsx | 是否有"全部错题""分类统计"和若干"知识点-xxx"表；数"全部错题"的数据行数，与 A3 初始条数 + A4 导入条数是否一致 |

**预计耗时**：12–20 分钟（含阅读与记录；不含排队等机器）。首次启动与首次分类会比后续慢，属正常，按实际数字记，不要"取整成好看的数字"。

**观察点（组织者记录）**

1. 启动是否需要在场帮助；是否需要读说明才会开。
2. 五个页面名称是否自解释；同学是否混淆"导入""分类""导出"三页。
3. 示例导入与自备 txt 导入的成功率；txt 格式是否被正确识别（段落空行分隔）。
4. 分类耗时与界面可用性（能否在分类中滚动列表）。
5. 修正是否"即时生效、无需保存、无需重启"；同学是否误以为要手动保存。
6. 重启后数据与修正是否留存。
7. 导出条数与预览是否一致；xlsx 能否被 Excel/WPS 正常打开。
8. 全程是否出现同学看不懂的中文提示。

**允许失败与记录方式**

- 任一步骤 2 次不成功即停止该步骤，在观察记录表"卡在哪里"写清：第几步、点了哪个按钮、屏幕上原话。
- 启动即失败（阻断）：抄下弹窗全文并截图；目录版可查工作区 `logs/app.log`；随后结束该同学的任务 A，不再尝试任务 B/C（B 依赖程序能启动），并登记问题（严重程度：阻断）。
- 导入 0 条成功：记录 txt 的实际编码与段落格式，不要当场改文件让同学重来（改了就不是同学的真实操作了）；如需重试，只允许用组织者另一份同格式文件再试 1 次。

### 2.2 任务 B：自定义体系（必须完成）

**前置条件**

**逐步操作**

| # | 做什么 | 看什么/记什么 |

| B1 | 进"分类体系管理"，点"新建分类体系"（或右上"新建体系"），名称如"高数-试用-微分方程"，学科选"高等数学"，确认 | 向导里有几个字段；哪个字段不知道填什么 |

5. "分类结果与依据"对非开发者是否可读。
6. 自动保存是否被感知（同学是否一直在找保存按钮）。

- B7 结果来自旧体系/内置体系：记录顶部下拉当时显示什么、是否点过"重新分类全部"，这是典型可用性缺陷线索。

### 2.3 任务 C：多模态流程（按需选做，必须事先备好素材）

**必须先告知同学的三件事**（组织者在开始前口头说明，并让同学在任务单上签字确认已被告知）：

3. 识别结果**必须人工核对**：模型输出不等于正确，尤其上下标、正负号、单位、英语否定词、数字和专有名词。

**逐步操作（图片，建议必做）**

### 5.3 无法验证时怎么写

- 没有干净机：在结题材料写"**未验证（无未安装 Python 的干净 Windows 设备）**"，并附现有证据及其边界（本机 Windows 11 冒烟通过，但本机装过 Python 与依赖，不能等同干净机）。

```
观察记录表（3.2）+ 问卷（第 4 节）
```

### 7.3 《真实试用与迭代记录》文档骨架

建议单独成文（约 4–8 页），结构如下，每节都必须有真实数据或明确写"未验证"：

1. **试用概况**：版本号、时间跨度、人数与专业分布、设备分布、任务完成率（分子/分母都写出来，例如"任务 A 完成 4/5"）。
2. **逐人记录摘要**：每人半页，写"做了什么、卡在哪、最后怎么完成的"，附截图编号。
3. **问题清单与严重程度分布**：阻断 __ 条、影响体验 __ 条、轻微 __ 条；列出阻断项全文。
4. **修复与复测**：每条问题的修复版本、改动要点、复测方式与结果；未修复项写原因。
5. **问卷结果**：逐题给频数（N=__），开放题按主题归类并**原文摘录**（去标识）；小样本不报百分比"满意率"。
6. **结论与局限**：能支持的结论（例如"3 名非开发者可在无提示下完成文本主流程"）、不能支持的结论（例如"不能据此推断分类准确率"）、未覆盖项（物理/英语场景是否覆盖、macOS、低配、干净机）。

### 7.4 与验收对照矩阵的关系

| 矩阵项 | 由谁提供证据 | 判定规则（建议） |
|---|---|---|
| 第 16 项 校内真实试用 | 本文件第 2–4、7 节 | 至少 3 名非开发者独立试用、覆盖高数/物理/英语三个场景、每人完成 A、有问题登记与至少一轮修复复测 → 可写"已完成"；任一项缺 → 写"部分完成（缺 ____）"，并写清人数与覆盖范围 |
| 第 13 项 全流程离线 | 第 5 节清单第 3、18 条 | 干净机断网全程无联网需求才算通过；开发机本地成功不算 |
| 第 14 项 干净 Windows 发布包 | 第 5 节清单 | 第 5–17 步全通过才算；缺媒体素材则该项写"部分验证" |
| 第 15 项 跨平台与低配 | 第 6 节 | 有目标设备实测才算；没有就保留"未验证"，不删项 |

三条纪律：

1. **一项证据只能支撑它真正覆盖的项。** 一次同学试用不能同时充当"干净 Windows 验证"——除非那台机器确实干净且清单走完。
2. **试用不产出准确率。** 准确率来自 155 条人工标注样本的主验收（98.1% / 纯文本 98.8%）；问卷第 6 题只是主观感受，写进材料时必须标明"主观评价，N=__"。
3. **状态只降不升。** 原矩阵里写"未完成"的，只有拿到对应证据才能改；改的时候把证据文件名写进备注，方便学校核查。

## 8 不能做什么（边界声明）

1. **自动化测试不能替代真实试用。** 826 项回归通过证明代码路径没坏，不证明一个没看过演示的同学能自己走完流程。回归结果不能填进观察记录表，也不能写成"试用通过"。
2. **开发者自测不能写成"同学试用"。** 项目组成员、帮忙调试过的同学、看过演示的人，都只能算内部测试。他们的记录可以进"内部测试"，不能进"校内真实试用"这一项。
3. **未发生的反馈不得补造。** 不填假日期、不凑人数、不编引语、不写"同学们普遍反映"。问卷必须由同学本人填；组织者不得代填、不得事后"整理"成通顺的句子当原话。
4. **示例数据不能当同学的题目。** 155 条内置示例用于演示与回归；用示例跑出来的结果，不能写成"同学用自己的错题完成了分类"。
5. **"有代码"不等于"已验证"。** 跨平台库、多平台分支、模型随包，都不能替代在目标系统上的实测。macOS、低配、干净机同理。
6. **本机不能冒充干净机或低配机。** 本机装过 Python、依赖和模型，且是当前开发机；把它写成"干净 Windows 验证通过"是造假。
7. **失败记录不能删。** 卡点、报错、放弃、需要人帮忙，都是结题材料里最有说服力的部分；只留成功记录会高估可用性，也会让"多轮迭代"失去依据。
8. **人数是执行建议，不是规定。** 3–5 人来自本方案，不是学校要求；材料里不得写成"按学校要求完成 5 人试用"。
9. **引用"已验证"只能按第 0.2 节的口径。** 事实卡没给的，一律写"未验证/待测"。
