## 摘要

本项目面向大学生日常错题整理"手动分类耗时、现有工具付费门槛高、分类逻辑固化、功能冗余不轻量"四类现实痛点，研发了一套可离线运行的 Windows 桌面错题自动分类系统。系统以 Python 为开发语言，以关键词粗筛加 TF-IDF 余弦相似度精匹配的**双层分级分类**为核心，辅以公式、图形、英语听力三类多模态错题的本地预处理，实现了错题导入、零代码自建分类体系、一键分类、人工修正与增量反馈、多维度 Excel 归档导出的完整闭环。

系统共实现 5 个主功能页面、约 60 个 Python 模块，内置高等数学、大学物理、大学英语、线性代数、概率论与数理统计 5 套学科分类体系（合计 44 个知识点标签），另附 1 套不含知识点的"通用"体系。自动化回归测试 **826 项全部通过**。按申报书规定的验收口径（基于 155 条人工标注的全类型错题样本），**知识点分类准确率 98.1%、纯文本错题准确率 98.8%、粗筛召回率 100%**，均达到申报书设定的指标。

项目同时存在明确未达标项，本报告如实列明：多模态错题（图片、公式、听力）从导入到输出分类结果的全流程耗时未达到"每题≤1 秒"的申报目标；人工反馈对同类题分类准确率的提升在独立实验中没有稳定达到 5%；校内同学真实试用已开展，记录见《真实试用与迭代记录》。上述内容在第七、八章逐条说明，不作回避。

## 二、立项背景与研究目标

### 2.1 要解决的问题

申报书调研了大学生错题整理的现状，归纳出四类痛点：

1. **手动整理效率极低。** 抄录、按知识点与错误类型逐一分类归档占用大量课余时间，且极易出现分类混乱、知识点对应错误。
2. **现有工具付费门槛高。** 主流错题软件的自动分类、批量导出、OCR、知识点匹配多需付费解锁会员，学生群体难以长期使用。
3. **分类适配性差。** 平台统一的知识点划分标准无法适配不同院校、不同教师的教学进度，"高等数学""大学物理"在不同学校的章节拆分差异明显。
4. **轻量化需求无法满足。** 多数错题软件附带题库、网课、刷题等冗余功能，体积大、流程繁琐，而学生的核心需求只是简单快速地完成分类。

### 2.2 研究目标

研发一套**轻量化、可离线、高适配**的错题自动分类管理系统，以经典成熟的 TF-IDF 权重计算与余弦相似度匹配作为纯文本分类的兜底方案，把创新点放在"大学生错题专属场景的多模态适配与分类策略优化"上，而不是重复发明基础算法。系统由多模态错题预处理、多特征融合分级分类、轻量化可视化交互三大单元构成，以 Python 为核心开发语言，整合支持本地 CPU 离线运行的轻量化开源工具链。

申报书列出的四项预期成果为：可落地使用的多模态错题自动分类系统程序；完整规范的开发资料与开源代码；贴合学习场景的实际应用成果（校内小范围试用）；团队专业实践能力的系统性提升。

## 四、技术路线与核心实现

### 4.1 四层架构

系统按申报书的技术路线实现为四层松耦合架构，各层之间通过标准化数据结构交互，可独立替换与优化：

```
多模态数据输入层   →  多模态特征预处理层  →  多特征融合分级分类层  →  可视化交互与结果输出层
手动/表格/图片/音频     文本·公式·图形·音频     关键词粗筛 → 融合精匹配        预览·修正·导出·备份
```

- **输入层**：格式校验与类型分流，统一为内部 `Question` 数据模型，附件统一归档到工作区并计算 SHA-256。
- **预处理层**：注册式可插拔单元，按 `audio → figure → formula → text_cn → text_en` 顺序执行，任一单元异常被捕获并记入特征包备注，不会中断整批分类。
- **分类层**：对每个启用的分类维度独立执行"粗筛—精匹配"。
- **输出层**：结果可视化、人工修正、按体系隔离导出、完整备份恢复。

### 4.2 双层分级分类的具体实现

**第一层：关键词快速粗筛。** 基于用户自定义的分学科知识点关键词库，对预处理后的多维特征词做匹配，筛出 3–5 个高相关候选标签。粗筛有三重兜底，保证未登录词也能命中：分词精确命中、`jieba.cut_for_search` 子词扩展命中、以及原文子串扫描（覆盖 3 字以上关键词）。这一步把精匹配的计算范围从"全部标签"缩到"3–5 个候选"。

**第二层：多特征融合精匹配。** 对候选标签，融合文本特征、公式特征、题型特征、学科特征，按错题类型与学科属性分配差异化权重，再用 TF-IDF 向量余弦相似度计算综合匹配度。

**TF-IDF 的增量实现。** 标签画像采用 base + delta 双层：base 层由用户配置的关键词与标准样本生成，delta 层由人工修正累积。用户改动关键词后重建 base 层，delta 层原样保留——这就是"改完立刻生效、不需要重启、不需要全量重训"的实现方式。文档频次统计按增量方式维护，避免每次重建都重算全量文档。

**一个刻意的设计取舍：不把体系关键词注入 jieba 全局词典。** 早期版本注入过，理由是"用户新加的多字关键词必须立刻被分词器认识"。实测这个理由是错的：粗筛已有三重兜底，精匹配两侧共用同一分词器，"切错但切得一致"仍能匹配；而代价很大——jieba 词典是进程级全局的，注入不可逆且跨学科污染（"分词作状语"注入后把"过去分词"整词吃掉），分类结果还会依赖"先同步过哪套体系"，同一道题换个操作顺序就换个结果。实测取舍：注入只换来 +0.6pp（155 条里 1 条，噪声量级），却把英语题核心特征提取准确率从 93.3% 压到 86.7%。因此改为不注入，并在代码注释中保留完整决策记录。

### 4.3 多模态预处理

| 模态 | 实现方式 | 关键设计 |
|---|---|---|
| 纯文本 | 文本清洗 → jieba 分词（分学科专有名词词典）→ "通用+学科专属"双层停用词 → 核心实词 | 中英混排分别走中、英两条分词链，保留原文 |
| 公式 | pix2tex（LaTeX-OCR，CPU 离线）识别公式图片或题干内联 LaTeX，经 `resources/formula_map.json` 的 85 条规则映射为知识点特征词 | 规则按"越靠前越具体"顺序匹配；`\int_a^b` 映射"定积分"、无上下限的 `\int` 映射"不定积分"，用符号结构区分纯文本无法区分的知识点 |
| 图形 | RapidOCR 本地识别图内标注文字与参数，并与用户补充标注融合 | 保留符号、原数值、单位、位置与来源；未校对的 OCR 参数与题干、人工标注分别保存 |
| 英语听力 | faster-whisper CPU int8 `base` 模型本地转写，再做英文分词、词形处理与专属停用词过滤 | 听力正文与题干问题/选项/标注共同保存；否定词、数字、专有名词为重点校对项 |

**识别结果的"三层分离"** 是这一层最重要的设计：**原始识别结果 / 用户草稿 / 确认内容** 三者分开保存。只有用户明确"确认"的内容才参与自动分类；保存草稿不应用新内容；修改已参与分类的草稿会使旧分类失效；识别失败或取消不覆盖题干与历史确认结果。

### 4.4 离线与打包

- 所有模型在运行期只读本地文件，识别进程启动时即把 `socket.connect`、`connect_ex`、`create_connection` 替换为抛异常函数，从机制上禁止联网。
- GUI 与识别进程使用两个独立 PyInstaller Analysis，媒体任务交给 `media_worker.exe`，通过文件传递请求与结果；这样"识别卡死或崩溃"不会带崩主界面。
- 公式识别因依赖 torch 与 pix2tex 的版本约束，放在随包携带的独立 Python 3.12 运行时（`formula_runtime/`）中执行，主程序无需安装 Python。

## 五、主要创新点

### 5.1 面向大学生错题场景的"粗筛—精匹配"双层分级分类

借鉴工业界文本分类的"粗排—精排"两阶段架构，针对错题场景做了定制：粗筛用用户自建的关键词库而非通用词表；精匹配融合公式、题型、学科、文本四类特征并做差异化加权。相比单阶段全量匹配，候选集从全部标签缩小到 3–5 个，降低了单条错题的计算量；同时保留经典方法轻量、稳定、可解释的优点，不需要模型训练，普通笔记本 CPU 即可运行。

### 5.2 零代码可自定义的多维分类体系

用户可以在界面上新建维度（知识点、错误类型、题目难度、复习优先级之外还可自建）、增删改标签、维护关键词、批量导入标准错题样本、调整标签特征权重，保存即生效、不需要改代码、不需要重启。这直接回应了"不同院校章节拆分不同"的痛点：分类体系由使用者定义，而不是由厂商固定。

### 5.3 分类修正驱动的增量反馈闭环

用户手动修正分类结果后，系统把修正内容提取为特征写入对应标签的 delta 层，增量更新文档频次与通道权重，不做全量重训。负反馈采用"每次总扣减预算"，避免把微小相似度差放大成固定最大步长；同时保留退步统计，不以"只会变好"为前提。

### 5.4 多模态分类全流程本地离线运行

从导入、公式识别、图文识别、音频转写到分类与导出，全部环节在本地完成，不调用任何云端接口，也没有付费功能门槛。软件打包后无需配置 Python 环境即可运行。

## 八、未达标项与局限说明

本章逐条说明差距，不掩饰、不改口径。

### 8.1 多模态错题全流程未达到"每题≤1 秒"

申报书 CASE 1 写"单条错题从导入到输出分类结果的全流程耗时≤1 秒"，CASE 2 写"全量错题平均分类耗时≤1 秒/条"。

实测（本机 Windows 11，发布包真实 exe，连续 3 轮 `--release-check`，2026-10-30 重建发布包后）：

| 场景 | 第 1 轮 | 第 2 轮 | 第 3 轮 |
|---|---|---|---|
| 图片文字识别（含进程启动） | 6.35 s | 1.96 s | 1.95 s |
| 31.88 秒英语音频转写 | 11.96 s | 2.08 s | 2.15 s |
| 裁剪公式图片识别 | 143.44 s | 7.02 s | 6.77 s |

**原因分析：** 纯文本分类是毫秒级的（平均 25.1 ms），瓶颈完全在模型推理与进程启动。图片 OCR 是轻量 CNN 检测+识别，热态约 2 秒；Whisper `base` 在 CPU 上做 31.88 秒音频的转写约 2 秒，已接近该模型在该硬件上的下限；公式识别需在独立 Python 3.12 运行时中加载 torch 与 pix2tex，热态约 7 秒，而全新构建后首次执行接近 2 分半钟（磁盘冷读 + 原生库初始化）。

**已做的优化：** 识别一律在独立进程执行，推理运行库异常不会拖垮界面；音频与公式在批量场景复用常驻进程。**图片相反——实测同一进程连续识别同一张图，耗时从 2.3 秒退化到 6.0 秒、再稳定在 11.4 秒，重建模型对象也无法恢复（2.3→9.2→12.7 秒），而每次新起进程连续 8 次都稳定在 2.3–2.5 秒**，因此图片改为一图一进程；修复后连续 4 张图片为 2.56–2.80 秒/张。**未做的取舍：** 没有为了凑指标换用更小的模型（会牺牲识别质量），也没有把识别时间排除在"全流程"之外来制造达标。

**处理意见：** 保留原指标、如实记录差异，由指导教师与学校判断是否接受。

### 8.2 人工反馈提升未稳定达到 5%

申报书写"确保修正后的同类型错题分类准确率提升≥5%"。项目按预注册的 3 个随机种子（17、42、2026）做"修正集 / 未见测试集"分离实验：

- 科学组：三次实验的提升分别为 0、−13.6、−2.5 个百分点，存在退步。
- 英语组：三次实验为 0、+13.3、+13.3 个百分点。

**原因分析：** 修正只更新被修正标签的 delta 特征与通道权重，样本量小时（修正集 86–111 条、测试集 79–104 条）权重变动会被少数样本主导，导致其他类型题退步。历史上同类子集曾出现 74.1%→81.5%（+7.4pp），但仅 27 条，划分敏感，不能作为稳定结论。

**处理意见：** 保留"修正立即生效、不全量重训"的机制（这是功能承诺，已实现并回归），但不宣称"每次使用都只会提高"。提升 5% 这一量化指标未获稳定证据，如实记录。

### 8.3 独立人工 gold 题库不足

项目用公开语料建立了独立语料集（OpenStax 190 题、SQuAD 30 题），来源、许可、原文、哈希均完整留存，但标签是**章节映射**（如"3 Derivatives"→"导数与微分"），不是人工逐题确认。项目提供了 `tools/review_acceptance.py` 的人工复核流程（导出 JSONL 供评测工具直接使用，且不向复核者展示模型预测以避免引导），但该复核尚未完成。

独立迁移测试结果偏低（科学 47.9%）的主要原因不是分类逻辑失效，而是**跨语言错配**：语料是英文，而系统的关键词库与学科词典是中文；系统通过 `scientific_terms` 中英术语桥接缓解，但英文原句的表述自由度远大于中文关键词覆盖面。这也解释了为什么英语阅读（26/30）明显好于科学（91/190）：英语体系的标签本身是题型级的，跨语言影响小。

**处理意见：** 该项作为"跨语言与未见表述的稳健性"证据如实报告，不用于支撑"≥90%"的达标结论；主达标结论依据申报书规定的 155 条人工标注集。

## 十一、存在的问题与改进方向

1. **多模态耗时。** 短期可做：识别进程常驻复用（批量已实现，单条可扩展为常驻服务）、按音频时长自适应选择模型规格、公式识别结果缓存。中期可评估更小的 Whisper 模型与量化方案，但需权衡识别质量。
2. **反馈效果稳定性。** 需要更精细的权重更新规则（按标签样本量自适应步长）与更大规模的独立复测；当前机制可用，但不宜宣称稳定增益。
3. **独立评测数据。** 补齐人工逐题确认的 gold 标签，并把中文真实错题纳入评测集，才能对"中文泛化能力"给出有说服力的结论。
4. **试用迭代。** 校内试用已完成并整理为《真实试用与迭代记录》，后续可继续补充第二轮；如交付范围扩展到其他平台，按《试用与外部验证方案》执行设备验证。
5. **跨平台。** 申报书提到 macOS，需在对应系统上实际构建与验证；如结题范围只做 Windows，应由指导教师确认。

## 十二、结论

项目按申报书的技术路线完成了一套可运行、可交付、可复现的轻量化错题自动分类桌面系统：四大核心模块与五大功能模块均已实现，多模态（文本、公式、图形、听力）预处理与双层分级分类链路贯通，零代码自建体系与人工反馈闭环可用，全流程本地离线运行，Windows 目录版发布包已实际构建并通过本机冒烟验证。

申报书设定的分类与特征提取类量化指标（7 项）全部达标，测试样本规模达标。两项指标未达标：多模态全流程耗时未达到每题 1 秒；人工反馈提升未稳定达到 5%。校内同学真实试用已开展并形成记录；交付与验收范围为 Windows x64，详见 8.4。上述差距已在报告中逐条列明原因与处理意见，相关证据与原始记录随材料一并提交，不作选择性呈现。

项目的实际价值在于：它用一套不依赖云端大模型、不需要模型训练、在普通笔记本上离线运行的方案，解决了大学生错题分类这个具体而真实的问题，并把"分类体系由用户定义、改完即生效"这一能力做成了可用产品。
