## 1. 交付范围

项目存在两种交付形态，包含内容不同，须分别说明：

| 形态 | 位置 | 包含内容 | 面向对象 |
|---|---|---|---|
| 源码交付 | 项目根目录（`main.py`、`app/`、`resources/`、`samples/`、`docs/`、`tests/`、`tools/` 等） | 全部 Python 源码、资源词典、语料与素材、文档、测试 | 二次开发者、评审教师 |
| 目录发布包 | `dist/错题自动分类/` | 已构建的可执行程序与随包模型、公式独立运行时、第三方许可、源码压缩包 | 直接使用者 |

### 1.1 源码交付包含什么

- **应用源码**：`app/` 下的界面、分类、预处理、数据读写模块，入口 `main.py`。
- **工具源码**：`tools/` 下的构建、打包、评测、模型准备、语料采集脚本。
- **测试源码**：`tests/` 下的 pytest 用例。
- **自有资源**：`resources/` 下的学科体系、分词词典、停用词、公式映射词典、科学术语表（共 10 个文件，见 2.1）。
- **语料与素材**：`samples/` 下三套验收数据及其 `LICENSE.txt`、`manifest.json`（许可见第 5 章）。
- **文档**：`docs/` 下 20 个文件，含使用手册、开发文档、发布说明与各类验收记录。
- **构建与运行配置**：`mistake_classifier.spec`、`requirements.txt` 及 5 个锁定/可选依赖文件、`启动软件.bat`、`安装图片识别.bat`、`.gitignore`。

### 1.2 目录发布包包含什么（已在本机核实）

`dist/错题自动分类/` 当前实际存在 13 个顶层条目：

```
错题自动分类.exe     media_worker.exe     _internal/          models/
formula_runtime/     docs/                samples/            third-party-licenses/
对应源代码.zip        LICENSE              README.md           开始使用.md

```

其中 `release-info.json` 记录了构建环境：Python 3.13.5、PyInstaller 6.22.3、`platform: win32`、`layout: onedir`、`clean_machine_verified: false`、`macos_verified: false`。

### 1.3 明确不在交付范围内的内容

| 内容 | 说明 |
|---|---|
| 用户题库与个人数据 | 默认工作区在用户目录 `.mistake_classifier`（`app/config.py` 的 `WORKSPACE_DIR`），不在项目目录内，也不随包分发。 |
| Python 安装包 | 不提供 Python 安装程序。主程序由 PyInstaller 打包，内含 Python 3.13 运行时；目标机无需另装 Python。 |

## 3. 复现步骤（从零开始）

以下命令以 Windows PowerShell / cmd 为准，项目绝对路径按 `D:\桌面\校创\mistake_classifier` 示例，实际使用时替换为自己的路径。

### 3.1 准备 Python 环境

要求 Python 3.11 以上，建议 3.12 或 3.13（本机验证环境为 3.13.5）。

```powershell
cd /d "D:\桌面\校创\mistake_classifier"
py -3 -m venv .venv
```

也可以直接双击 `启动软件.bat`，它调用 `tools/launch.py`，首次运行会在项目内创建 `.venv` 并联网安装核心依赖（需要网络）。

### 3.2 安装依赖

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`requirements.txt` 的核心依赖：jieba、scikit-learn、numpy、scipy、pandas、openpyxl、PyQt5。需要可复现的环境时，改用锁定文件 `requirements-lock-windows.txt`（其中固定 PyQt5==5.15.11、jieba==0.42.1、scikit-learn==1.9.1、numpy==2.5.4、pandas==3.1.0、rapidocr==3.10.0、onnxruntime==1.31.1、faster-whisper==1.2.1、av==19.0.2、pyinstaller==6.22.3）。

需要图片文字识别时：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-ocr.txt
```

或双击 `安装图片识别.bat`（等价于 `tools\launch.py --install-ocr`）。该组件自带约 30.3 MiB 本地模型。

需要听力转写时：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-media.txt
```

构建工具单独锁定在 `requirements-build.txt`（`pyinstaller==6.22.3`、`pyinstaller-hooks-contrib==2026.9`）。

### 3.3 公式识别独立环境（可选）

公式识别因 torch 版本约束，使用独立的 Python 3.12 环境，与主环境隔离：

```powershell
py -3.12 -m venv .venv-formula
.\.venv-formula\Scripts\python.exe -m pip install -r requirements-lock-formula-windows.txt
```

该锁定文件对应 Python 3.12.13，torch 2.5.1+cpu、pix2tex==0.1.4（CPU wheel 来自 download.pytorch.org/whl/cpu）。不装公式组件时，题干中用 `$...$` 手写的公式仍可正常识别与分类。

### 3.4 准备模型

```powershell
# 仅查看模型状态，不下载、不安装
.\.venv\Scripts\python.exe tools\check_media_models.py

# 先看说明；确认联网后再加 --download
.\.venv\Scripts\python.exe tools\prepare_media_models.py
.\.venv\Scripts\python.exe tools\prepare_media_models.py --download
```

听力模型默认落在 `%USERPROFILE%\.mistake_classifier\models\audio`，可用 `--model-dir` 或环境变量 `MC_MODEL_DIR` 改到项目内（打包时建议指到项目目录，便于 `stage_release.py` 收集）。

公式模型由 `tools/prepare_formula_models.py` 准备，下载后写入带 SHA-256 的 `manifest.json`。程序在识别前校验文件，不隐式下载。

### 3.5 运行

```powershell
.\.venv\Scripts\python.exe main.py
```

或双击 `启动软件.bat`（图形界面脱离终端运行，日志写入根目录 `启动日志.txt`）。

### 3.6 跑测试

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

发布前应重新执行并把结果写入 `docs/自动化回归记录.json`（该文件目前是历史记录，本文不引用其历史通过率作为当前结论）。

### 3.7 构建发布包（关键：中文路径必须用 ASCII subst 映射盘）

已确认的失败模式：项目路径含中文时，PyQt5 5.15 的 `QLibraryInfo` 会返回有损的插件路径，Qt 插件解析失败，界面初始化卡住。`tools/build.py` 的 `validate_build_environment()` 会在构建前检查这一点并直接报错：

> Qt 构建插件目录无法解析：……。请从 ASCII 路径的 subst 映射盘运行项目解释器。

因此构建步骤为：

```powershell
# 1) 把项目根目录映射到 ASCII 盘符
subst S: "D:\桌面\校创\mistake_classifier"

# 2) 必须切到映射盘，build.py 用当前工作目录判定项目根
cd /d S:\

# 3) 用映射盘上的解释器构建（目录版是当前唯一受验证的模式）
S:\.venv\Scripts\python.exe tools\build.py --onedir

# 4) 组装发布目录：模型、公式运行时、第三方许可、源码包
S:\.venv\Scripts\python.exe tools\stage_release.py "S:\dist\错题自动分类" --model-dir "S:\models" --formula-python "S:\.venv-formula\Scripts\python.exe"

# 5) 静态核验（检查 exe、_internal、release-info.json 等必需项并计算 SHA-256）
S:\.venv\Scripts\python.exe tools\validate_release.py "S:\dist\错题自动分类" --binary

# 6) 构建完成后解除映射
cd /d D:\
subst S: /D
```

说明：

- 只映射一个盘符即可，`subst S: /D` 用于解除；`subst` 不带参数可列出当前映射，确认已清理。
- 本机历史构建日志 `build_ascii.log` 使用的是 `M:` 盘（`Python environment: M:\.venv`），说明当时确实通过映射盘构建；日志中的模块搜索路径仍打印了中文原路径，属正常现象。
- `stage_release.py` 要求目标目录已存在 `错题自动分类.exe` 与 `media_worker.exe`，否则直接报错退出；`--formula-python` 必须与 `--model-dir` 同时给出。
- 构建会生成 `mistake_classifier.spec` 与 `release-info.json`，并把 `README.md`、`LICENSE`、`开始使用.md` 复制进发布目录。
- 解除映射后不要再用原路径重新构建，否则会复现 Qt 插件路径问题。

- `tools/stage_release.py` 的 `stage_licenses()` **不含任何硬编码许可清单**。它遍历构建环境里 `importlib.metadata.distributions()`，把 `.dist-info` 中文件名含 `license`/`copying`/`notice` 的文件原样复制到 `third-party-licenses/<包名>/`，并写出 `installed-components.json`。该文件自述范围为"构建环境的已安装依赖；包含开发工具，非逐一判定为发布程序所需组件"。

### 4.3 PyQt5 的 GPL v3 约束（本项目最大的合规缺口）

事实：`PyQt5` 的 `METADATA` 写明 `License: GPL v3`；项目自己的 `LICENSE` 第 31–42 行也专门提示了这一点。

后果：

1. **源码分发不受影响**。项目源码是 MIT，MIT 与 GPL v3 兼容，可以被并入 GPL 作品。
2. **分发 `dist/错题自动分类/` 里的 exe 时，整个产物需按 GPL v3 处理**：须向接收者提供 GPL v3 许可文本，并提供对应的完整源码。发布包内已有 `对应源代码.zip`（260 个条目，含 `app/`、`resources/`、`samples/`、`docs/`、`tests/`、`tools/`、`LICENSE`、各 `requirements*.txt` 与 `source-manifest.json`），这一步在形式上已具备条件。
3. **但 `third-party-licenses/` 里没有 PyQt5 的 GPL v3 许可文本**——`installed-components.json` 中 `PyQt5` 的 `license_files` 为空数组，因为该 wheel 的 `.dist-info` 内没有名为 license/copying/notice 的文件。**发布前必须手工补齐**。
4. 替代方案（供项目组决策，本文不代为选择）：换用 LGPL 授权的 PySide6，或购买 PyQt5 商业许可，或接受整个打包产物按 GPL v3 发布并完整履行源码提供义务。

## 8. 使用规范与二次开发指引

### 8.1 新增一个学科

1. `app/config.py`：在 `SUBJECTS` 列表中加入学科名；若该学科走英文预处理，同时把它加入 `SUBJECT_LANG`（值为 `"en"`），否则默认走中文分支（`DEFAULT_LANG = "zh"`）。该列表直接驱动导入页与体系管理页的学科下拉框（`app/ui/pages/page_import.py`、`page_scheme.py`）。
2. `resources/userdict/`：新增 `<学科>.txt`，格式为 `词语 词频 词性`（每行，首行可写注释），例如 `洛必达法则 2000 nz`。分词不识别专有名词时，关键词永远匹配不上。
3. `resources/schemes/builtin_schemes.json`：新增一套体系对象（字段：`id`、`name`、`subject`、`description`、`builtin`、`revision`、`dims`）。`dims` 中每个维度为 `{key, name, enabled, labels}`，`labels` 中每个标签为 `{id, name, dim, keywords, keyword_weights, samples, weight_override, prior, note}`。`keywords` 与 `samples` 决定召回与精匹配质量。
4. 可选：`resources/stopwords/subject_common.txt` 增补该学科的高频套话（如"如图所示"），这类词出现率高但无判别力。
5. `app/core/classify/weights.py`：在 `DEFAULT_RULES` 中为新学科补权重桶；不补时会落到 `("*", qtype)` 或 `("*", "*")` 兜底桶。

### 8.2 扩展公式映射词典

- 数据文件：`resources/formula_map.json`，字段 `subject`（`"*"` 表示全学科通用）、`pattern`（Python 正则，匹配 LaTeX 源码）、`tokens`（命中后注入的知识点特征词）、`weight`（重复注入次数，越大越具判别力）、`note`。
- 生成器：`tools/build_formula_map.py`（文件头注释写明了字段含义与"按列表顺序匹配，越靠前越具体"的规则）。**注意：该脚本会整体重写 `resources/formula_map.json`**。要长期维护，应改脚本后重跑；要临时试验，可直接改 JSON，但下次重跑会被覆盖。
- 顺序敏感：带上下限的 `\int` 必须排在裸 `\int` 之前，否则定积分会被判成不定积分。
- 学科隔离：规则按 `subject` 生效，`E=mc^2` 在物理题里映射为"质能方程"，在高数题里不应产生特征。
- 现状与文档差异：`resources/formula_map.json` 实为 **85 条**规则（字段名为 `subject`），而 `docs/开发文档.md` 第 117 行写作"82 条规则"且示例字段为 `subjects`。以实际文件为准，文档需同步。
- 新增规则后建议跑 `tests/test_formula_mapping_boundaries.py` 与 `tools/check_formula_examples.py`。

### 8.3 调整分类权重与阈值

| 目标 | 位置 | 配置项 |
|---|---|---|
| 改某学科某题型的通道权重 | `app/core/classify/weights.py` 的 `DEFAULT_RULES` | 键为 `(学科, 题型)`，值为 `{文本, 公式, 题型, 学科}`，例如高数公式题为 `{0.35, 0.45, 0.10, 0.10}`；键支持 `"*"` 通配 |
| 改单个标签的权重 | 分类体系 JSON 的标签字段 `weight_override` | 语义是"在该桶权重之上打补丁"，不会丢弃其它通道已学到的权重 |
| 改粗筛候选数 | `app/config.py` | `COARSE_TOP_K = 5`、`COARSE_MIN_K = 3` |
| 改粗筛命中权重 | 同上 | `COARSE_KEYWORD_WEIGHT = 1.0`、`COARSE_SUBSTR_WEIGHT = 0.6`、`COARSE_LEARNED_WEIGHT = 0.55`、`FEEDBACK_KEYWORD_TOPN = 8` |
| 改关键词放大倍数 | 同上 | `LABEL_KEYWORD_BOOST = 3.0` |
| 改低置信提示阈值 | 同上 | `LOW_CONFIDENCE_THRESHOLD = 0.15`、`COARSE_ONLY_CONFIDENCE = 0.5` |
| 改在线学习强度 | 同上 | `FEEDBACK_POSITIVE_GAIN = 1.0`、`FEEDBACK_NEGATIVE_DECAY = 0.25`、`WEIGHT_LEARNING_RATE = 0.08`、`WEIGHT_MIN = 0.02` |
| 改单题时间预算常量 | 同上 | `SINGLE_QUESTION_TIME_BUDGET_MS = 1000`（这是需求约束常量，不改变实际耗时） |

权重在线学习的规则是"只改具体 `(学科, 题型)` 桶"，改动通配桶会让一次人工修正污染全局。

### 8.4 二次开发的边界提示

- 可选识别引擎均为 try-import + 标志位，缺依赖时降级而非崩溃（`app/core/preprocess/pipeline.py` 的 `engine_report()`，界面"环境自检"直接渲染它）。新增引擎请沿用这一模式。
- 分类链路必须保持"无需全量重训"：增量 TF-IDF 由 `app/core/classify/vector_space.py` 自行维护 `vocab`、`df`，不要改成 `TfidfVectorizer.fit()`。
- 界面与识别进程是两个独立 PyInstaller Analysis，通过文件传递任务（`media_worker.exe`）；改动 `tools/build.py` 的 spec 生成部分时，不要合并这两条分析。
- 修改后至少运行 `tests/`，并按 3.7 重新构建与核验。
