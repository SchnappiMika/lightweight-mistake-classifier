### 1.4 术语与缩写

| 术语 | 含义 |
|---|---|
| 分类体系（Scheme） | 一套完整的分类规则集合，含所属学科、若干分类维度及维度下的标签，是分类、导出、备份的基本单位 |
| 分类维度（Dimension） | 体系内的一条分类轴线，内置知识点、错误类型、题目难度、复习优先级四类，也可由用户自定义 |
| 标签（Label） | 维度下的具体类别，携带关键词、标准样本与可选的权重覆盖 |
| 关键词粗筛 | 双层分类的第一层，用倒排索引从全部标签中挑出少量候选 |
| 多特征融合精匹配 | 双层分类的第二层，对候选标签做文本、公式、题型、学科四通道的 TF-IDF 余弦匹配并加权融合 |
| 特征通道 | 精匹配的输入分项，共文本、公式、题型、学科四个通道 |
| 标准样本 | 用户贴入某个标签的典型题干，作为该标签画像的第二个来源 |
| 草稿 / 确认 | 媒体识别结果的两种状态；只有"确认"后的内容才参与分类 |
| 工作区 | 用户目录下的可写数据目录（默认 `~/.mistake_classifier`），存放题目、体系、媒体、学习数据、导出与日志 |
| 可选组件 | 图片文字识别、公式识别、听力转写三类本地引擎；未安装时系统降级运行而不报错退出 |

## 2 项目背景与问题陈述

### 2.1 背景

申报书指出，在国家教育数字化战略行动持续推进、《教育信息化2.0行动计划》要求推进信息技术与教育教学深度融合的背景下，错题整理是学生巩固知识点、补齐学习短板的核心环节。各类错题管理软件数量不少，但在"面向普通大学生日常轻量化使用"这一具体场景中仍存在明显缺口。

项目组的判断是：缺口不在算法本身，而在"大学生真实错题场景"与"现有工具的产品形态"之间不匹配。因此本系统把经典文本分类方法（TF-IDF 权重计算与余弦相似度匹配）作为兜底，把研发重心放在多模态错题的适配、可自定义的分类体系与反馈迭代机制上——这一点在申报书"研究内容"中被明确表述为"核心创新聚焦于大学生错题专属场景的多模态适配与分类策略优化，而非基础算法的重复发明"。

### 2.2 问题陈述

申报书列出四类问题，它们直接转化为本系统的需求约束：

| 编号 | 问题 | 申报书原文要点 | 对系统的需求约束 |
|---|---|---|---|
| P-1 | 手动整理效率极低 | 需手动抄录错题、按知识点与错误类型逐一分类归档，占用大量课余时间，且易出现分类混乱、知识点对应错误 | 必须提供自动分类能力，不能把"打标签"继续留给用户；导入到出结果应尽量少的中间步骤 |
| P-2 | 现有工具门槛过高 | 自动分类、批量导出多需付费解锁会员，OCR 与知识点匹配另需单独付费 | 全流程免费、无付费墙；识别与分类在本地完成，不依赖付费云服务 |
| P-3 | 分类适配性较差 | 分类逻辑固定，采用平台统一的知识点划分，无法适配不同院校、不同教师的教学进度与知识点拆分 | 分类体系必须零代码可自建、可改、可分享；新建维度与标签不得要求改代码或重启 |
| P-4 | 轻量化需求无法满足 | 功能冗余，附带题库、网课、刷题等附加功能，软件体积大、流程繁琐 | 只做错题分类归档主线，不引入题库、网课、刷题、社区等模块；安装与启动流程尽量短 |

### 2.3 由问题推导出的场景特征

四类问题共同指向几个场景特征，它们构成第 4 章使用场景与第 5 章功能需求的现实基础：

- **错题来源分散、格式不统一**：纸质拍照、课件截图、听力音频、电子文档、手工录入并存，要求入口层支持多格式而不要求用户预先转换。
- **学科跨度大、题型差异大**：高等数学公式题、大学物理图形题、大学英语听力与阅读题、文科纯文本题的有效分类信息载体完全不同，单一纯文本流水线无法覆盖。
- **分类标准因人而异**：同一门课在不同院校、不同教师下的章节拆分与术语习惯不同，固定体系必然错位。
- **使用环境不稳定**：自习室、图书馆、宿舍网络条件不一，系统不能因为断网而不可用。
- **用户不写代码**：目标用户没有编程基础，任何"改配置要编辑文件"的设计都不可接受。

### 2.4 技术定位

申报书把技术路线定为四层松耦合架构：多模态数据输入层、多模态特征预处理层、多特征融合分级分类层、可视化交互与结果输出层。本文的功能需求按这条分层组织，并遵守三条由技术定位决定的硬约束：

1. **不引入大模型与深度学习训练流程**，普通笔记本 CPU 即可运行；
2. **分类结果可解释**，用户能看到粗筛命中了哪些词、各通道打了多少分，而不是只拿到一个标签；
3. **学习机制必须增量**，人工修正后不得要求全量重新训练。

## 3 干系人与用户画像

### 3.1 干系人

| 干系人 | 角色 | 主要关注点 | 对需求的影响 |
|---|---|---|---|
| 在校大学生 | 最终用户（主要） | 导入快、分类准、能按自己的章节归档、不要付费 | 决定易用性、零代码、离线、免费四项需求 |
| 任课教师、指导教师 | 使用建议者与验收方 | 分类维度能否贴合教学大纲；学生学业数据不外传 | 决定维度/标签可自定义、全程本地存储 |
| 项目团队 | 开发与维护方 | 模块边界清晰、可分工、可测试、可打包 | 决定分层架构、核心层与界面解耦、可选依赖降级 |
| 学校与评审专家 | 结题归档验收方 | 材料完整、指标如实、成果可复现 | 决定文档体系、指标口径必须写清、不得把未验证写成已验证 |
| 同校学生与开源使用者 | 二次开发者 | 代码可读、能加学科库与新模态 | 决定可扩展性需求与开源交付要求 |

项目团队分工（引自申报书）：陈宇翔统筹进度与技术路线，负责整体架构与核心分类逻辑；朱倩颖负责多模态预处理与分学科关键词库、专有名词词典；郭雨翰负责 PyQt 界面与打包适配；谢许诺负责测试用例、测试报告与文档归档。

### 3.2 用户画像

**U1 学生用户（主要画像）**

- 特征：无编程基础；使用普通笔记本；常在断网或弱网环境自习；错题分散在照片、截图、音频和电子文档中。
- 目标：把一批错题尽快归到自己认可的章节下，导出成能打印复习的表格。
- 痛点：不愿为分类功能付费；不愿学新工具的操作逻辑；担心错题与成绩数据被上传。
- 对应需求：多格式导入、零代码体系、一键分类、分 sheet 导出、全流程离线。

**U2 教师用户（次要画像）**

- 特征：有自己的章节划分与术语习惯，会按班级进度调整知识点粒度。
- 目标：把分类维度改成与讲义一致；看清学生共性错因。
- 痛点：通用工具的知识点体系与自己的教学顺序对不上。
- 对应需求：自定义维度与标签、关键词与标准样本可编辑、体系可导出分享、错误类型维度可单独统计。

**U3 团队与二次开发者**

- 特征：需要读源码、替换或新增预处理单元、扩展学科库。
- 目标：在不破坏既有分类逻辑的前提下扩展能力。
- 对应需求：可插拔预处理单元、核心层不依赖界面框架、构建脚本可重新打包。

### 3.3 系统定位

本系统定位为**个人离线轻量桌面工具**，这一定位直接划定了一批"不需要做"的需求：

- 单机、单用户，不设账号、登录、权限与角色体系；
- 不设服务端，不调用云端接口，不做云同步；
- 不做题库、搜题、网课、刷题、社交等附加模块；
- 多人共享知识库的方式是导出/导入体系 JSON 文件，而不是协作编辑；
- 换机迁移由"完整备份与恢复"承担，而不是账号漫游。

需要强调的是，这一定位来自 P-2 与 P-4：付费门槛与功能冗余正是项目要规避的两个问题，因此"少做"本身就是需求的一部分。

## 4 使用场景

本章场景编号沿用申报书 4.4.2 的 CASE 1—6，便于与申报材料逐条对照。每个场景给出场景描述、前置条件、主流程、期望结果与对应需求编号。

### CASE 1 单条多模态错题快速分类

- **场景**：学生做完一道题发现做错，想立刻归档，题面可能是公式截图、物理图形照片、英语听力音频或一段文字。
- **前置条件**：软件已启动；已选定或已内置对应学科的体系；媒体类题目已准备好本地文件。
- **主流程**：单条录入或导入一个文件 → 系统自动判断学科与题型 → 需要时对图片/音频做识别与人工校对 → 确认后一键分类 → 查看分类依据。
- **期望结果**：单条题目从导入到得到分类结果的过程不需要手工打标签；结果附带置信度与依据，低置信时提示复核。
- **对应需求**：FR-01、FR-03、FR-06、FR-07、FR-08、FR-17 至 FR-20。

### CASE 2 跨学科多模态批量错题分类

- **场景**：期末复习，学生把一学期积累的错题（纯文本、公式图片、图形照片、听力音频混在一起）一次性导入。
- **前置条件**：错题已整理为 TXT/Excel 文件或集中在若干文件夹；体系已按学科建好或使用内置体系。
- **主流程**：批量导入文件与目录 → 去重与失败项提示 → 批量分类（后台执行、可停止）→ 逐条查看与批量修正 → 导出。
- **期望结果**：批量过程不卡界面、不丢数据；单条失败不影响整批；混合学科时每道题使用其学科对应的体系。
- **对应需求**：FR-02 至 FR-05、FR-22、FR-25。

### CASE 3 零代码自定义分类体系适配

- **场景**：学生所在班级的《高等数学》按教师讲义拆成与内置体系不同的章节，需要系统按新章节分类。
- **前置条件**：已打开分类体系管理页。
- **主流程**：新建体系并选学科 → 新建或调整维度 → 逐标签填关键词、贴标准样本 → 需要时设置特征权重 → 回到分类页直接使用。
- **期望结果**：配置保存后立即生效，不需要重启软件，也不需要改任何代码；配置可导出给同学复用。
- **对应需求**：FR-10 至 FR-16。

### CASE 4 分类结果反馈增量优化

- **场景**：学生发现某类题被判错，手工把标签改对，希望系统以后同类题判得更准。
- **前置条件**：该题已有分类结果；体系已配置关键词或样本。
- **主流程**：在分类页逐维度下拉修正 → 系统即时更新标签画像、通道权重与粗筛索引 → 在反馈页查看学到了什么、权重如何变化。
- **期望结果**：修正立即生效且不触发全量重训、不联网；学习过程可见、可导出、可回滚。
- **对应需求**：FR-21、FR-23、FR-24。

### CASE 5 无网络环境全流程离线使用

- **场景**：校园网不稳定或完全断网的自习环境。
- **前置条件**：依赖与本地模型已在有网时准备完成；运行期不再下载。
- **主流程**：导入 → 预处理（文字/公式/转写）→ 分类 → 修正 → 导出 → 备份，全程不访问网络。
- **期望结果**：断网不产生功能限制，也不出现"必须联网才能用"的功能分支；缺失本地模型时给出明确原因而不是静默失败。
- **对应需求**：NFR-1、FR-06 至 FR-08。

### CASE 6 分类结果个性化导出

- **场景**：学生要把错题按知识点做成可打印的表格，把图片和音频按标签整理成文件夹，或把整套数据打包迁移到另一台电脑。
- **前置条件**：题目已分类；已选定体系与导出维度。
- **主流程**：选择分 sheet 维度 → 查看导出结构预览 → 导出 Excel / 导出媒体归档 → 需要迁移时创建完整备份，在新机器上恢复。
- **期望结果**：Excel 每个标签一个 sheet、含总表与统计表；媒体按标签分文件夹并带索引；备份可在另一台机器完整还原题目、体系、学习数据与附件。
- **对应需求**：FR-25 至 FR-29。

## 5 功能需求

本章按申报书 4.3.2 的五大核心功能模块组织，共 29 条功能需求（FR-01 至 FR-29）。每条需求给出输入、处理、输出与异常四要素，优先级见 8.1 节。

模块 E 在申报书第 5 模块（个性化导出）基础上补充了备份与恢复需求。补充原因是：系统定位为个人离线工具，没有账号与云端，换机、重装、误删后的数据保全只能由本地备份承担，因此备份与恢复属于必要需求，而非附加功能。

### 5.1 模块 A：多模态错题导入与预览（FR-01—FR-09）

**FR-01　单条手工录入**（优先级 P0）

- **输入**：题干文本（可用 `$...$` 包裹内联公式）、可选标注、可选学科与题型、可选附件。
- **处理**：未指定学科或题型时，根据题干文本与附件扩展名自动推断；带附件时先把文件复制进工作区，避免依赖原始路径。
- **输出**：一条题目记录，来源标记为手工录入，进入列表并可直接参与分类。
- **异常**：题干为空且无附件时拒绝创建；附件复制失败时保留已填文本并提示，不产生半条记录。

**FR-02　批量文件导入（TXT / CSV / TSV / XLSX）**（优先级 P0）

- **输入**：TXT（空行分段或一行一条，`#` 开头为注释）、CSV/TSV/XLSX（表头可为"题干/题目/错题/内容/question"等同义词）。
- **处理**：文本文件按 UTF-8-sig、UTF-8、GBK、GB18030、Big5、UTF-16 顺序尝试解码；表格按列名同义词映射到题干、学科、题型、标注、附件、优先级；题型列的中英文别名统一归一；表头无法识别时以第一列为题干；附件列支持相对表格目录的路径并在导入时复制入工作区。
- **输出**：批量题目记录、导入条数统计。
- **异常**：文件不存在、编码不可识别、无有效内容时给出明确错误且不写入；单行或单个附件失败不影响其余行（进入错误详情）；旧版 `.xls` 提示另存为 `.xlsx`。

**FR-03　媒体文件与整目录导入**（优先级 P0）

- **输入**：图片（png、jpg、jpeg、bmp、webp、tif、tiff）、音频（wav、mp3、m4a、flac、ogg、aac、wma），或一个包含上述文件的目录。
- **处理**：按扩展名分流并复制进工作区媒体目录，生成题干可为空的题目记录，供后续识别与预览。
- **输出**：媒体题目列表，可预览图片、播放音频。
- **异常**：不支持的扩展名跳过并计数；复制失败保留错误信息；同一文件被重复导入时由 FR-04 处理。

**FR-04　附件归档与导入去重**（优先级 P1）

- **输入**：待导入的题目集合与附件。
- **处理**：附件统一归档到工作区媒体目录，内容相同的附件复用不重复占用；去重指纹覆盖题干、标注、学科、题型、复习优先级与附件内容（附件按 SHA-256 摘要），默认跳过完全重复的题目，用户可取消勾选以保留重复项。
- **输出**："新增 N 条、跳过重复 M 条"的导入摘要。
- **异常**：关闭去重时保留全部记录；附件缺失的题目仍保留，但在列表中标注为仅附件或空题干状态。

**FR-05　部分失败保留与失败重试**（优先级 P1）

- **输入**：一次批量导入中失败或未处理的文件、表格行。
- **处理**：成功项先保存入库；失败项记录可展开的原因；"重试失败的导入"只重跑失败项，默认跳过已成功导入的重复题目。
- **输出**：导入结束摘要与可展开的错误详情、重试结果。
- **异常**：重试仍失败时保留上次错误信息；用户修正源文件后可再次重试；重试不会重复插入已成功的行。

**FR-06　图片文字识别与校对**（优先级 P1）

- **输入**：一条含图片附件的题目、已选学科。
- **处理**：本地图片文字引擎在独立进程后台识别，避免阻塞界面；识别结果包含原文、逐行文本与逐行分数，原文只读保留，校对文本可编辑；"保存校对草稿"只保存草稿，"应用为题干"才更新题干并作废旧分类。
- **输出**：识别原文、逐行分数、校对草稿、应用状态；导出时附带图片识别状态。
- **异常**：图片超过尺寸上限或像素上限、无识别文字、模型缺失或损坏时给出具体处理建议；识别期间可取消且原有内容不变；保存失败时编辑内容留在窗口内，关闭前提示确认。

**FR-07　公式识别与 LaTeX 校对**（优先级 P1）

- **输入**：公式图片，建议先裁剪为单个公式。
- **处理**：在独立 Python 3.12 环境内调用本地公式识别组件推理，返回 LaTeX；用户对照原图校对后确认；确认后的 LaTeX 经公式—知识点映射规则（`resources/formula_map.json`）转换为知识点特征词，与文本特征融合后参与分类。
- **输出**：LaTeX 文本、映射出的公式特征词、确认状态。
- **异常**：组件或模型缺失时降级为仅使用题干内联公式与人工标注，并说明原因；多公式混排的整幅图片识别结果不可靠，引导用户裁剪后重试；未确认的草稿不参与分类。

**FR-08　听力音频转写与校对**（优先级 P1）

- **输入**：英语听力音频。
- **处理**：本地转写引擎（faster-whisper `base` 模型、CPU int8）后台转写，返回草稿与分段结果；用户校对并确认后，结合题干、问题与标注提取英文场景词、知识点词与题型特征词。
- **输出**：转写草稿、确认状态、英文特征词。
- **异常**：组件或模型缺失时保留原题并给出失败原因；长音频转写耗时长，界面显示进度、允许取消且不冻结界面；未确认的草稿不参与分类。

**FR-09　预览、检索与标注补录**（优先级 P1）

- **输入**：检索词、学科与题型筛选条件、标注文本。
- **处理**：检索范围覆盖题干、标注与附件文件名，不区分英文大小写，与学科、题型筛选同时生效；标注与题干一并参与分类；针对图形题与听力题给出标注提示（图中元件、标注参数、考查知识点；场景、关键信息、题型）。
- **输出**：筛选后的列表、条目详情（学科、题型、题干、图片与音频预览、标注区）、匹配数量。
- **异常**：编辑后不再满足筛选条件的条目移出列表，但右侧编辑区保留；"单条录入"清空检索并沿用当前筛选，避免新题被隐藏；音频后端缺失时降级为用系统播放器打开，不影响转写与分类。

### 5.2 模块 B：零代码分类体系管理（FR-10—FR-16）

**FR-10　内置学科体系**（优先级 P0）

- **输入**：首次启动或用户选择恢复内置体系。
- **处理**：从资源文件载入内置体系：高等数学（10 个知识点标签）、大学物理（14 个）、大学英语（9 个）、线性代数（5 个）、概率论与数理统计（6 个），每套另含错误类型、题目难度、复习优先级三个维度；此外提供 1 套不含知识点维度、仅含错因/难度/优先级的"通用"体系。
- **输出**：开箱可用的体系树，用户无需先建体系即可完成第一次分类。
- **异常**：内置资源缺失或损坏时提示并可改为新建体系；"恢复内置体系"只重建内置项，不删除用户自建体系。

**FR-11　体系的建立、修改与删除**（优先级 P0）

- **输入**：体系名称、所属学科、描述。
- **处理**：支持新建、改名、改描述、删除；体系带单调递增的版本号，任何修改都会使已缓存的特征库失效并在下次使用时重建。
- **输出**：更新后的体系树，各页面体系下拉框同步刷新。
- **异常**：空名称拒绝；删除体系时其题目保留，但相关分类结果作废，需要在重新选择体系后再分类；体系名称重复时允许并存，需用户自行区分。

**FR-12　自定义分类维度**（优先级 P0）

- **输入**：维度名称、启用状态。
- **处理**：内置知识点、错误类型、题目难度、复习优先级四个维度可启用或停用；用户可新增任意维度（如章节、失分原因、复习轮次）；停用的维度不参与分类，也不出现在导出分 sheet 选项中。
- **输出**：维度列表与体系树节点。
- **异常**：空名称拒绝；重名提示；删除含标签的维度需二次确认。

**FR-13　标签与关键词库**（优先级 P0）

- **输入**：标签名称、关键词（一行一个）、可选的标签级权重覆盖。
- **处理**：关键词写入标签画像并进入粗筛倒排索引；关键词过少时界面提示补充；保存后体系版本号递增，分类引擎在下次分类时重建特征库。
- **输出**：标签节点、关键词数量、体系统计（标签数、关键词数、样本数、已学习修正次数）。
- **异常**：空标签名或空关键词拒绝；重复关键词去重保序；未填关键词的标签在粗筛阶段不会被选中，界面就此给出明确提示，避免用户误以为"系统不准"。

**FR-14　标准样本与批量导入样本**（优先级 P1）

- **输入**：典型题题干（单条或多条）、批量样本文件。
- **处理**：样本作为标签画像的第二个来源参与精匹配，关键词在画像中的权重高于样本；分类页可把一条已分类题目"采纳为标准样本"，固化进体系并随体系导出。
- **输出**：标签样本列表、更新后的画像。
- **异常**：重复样本拒绝重复更新；空样本不写入；批量导入格式错误时给出可定位的提示。

**FR-15　特征权重配置**（优先级 P1）

- **输入**：默认配置，或用户为某个标签单独指定的通道权重。
- **处理**：默认按"学科 × 题型"分桶分配四通道权重（公式类更重公式通道，英语听力更重文本与题型通道）；标签级覆盖是该桶权重之上的补丁，既不退回全局兜底规则，也不丢弃系统已从反馈中学到的权重；某通道无特征时，其权重按比例再分配给其余通道，避免纯文本题被系统性压低置信度。
- **输出**：生效权重表、反馈页的权重条形图。
- **异常**：非法或全零权重拒绝；"重置权重规则"只恢复默认权重，不清除已学到的特征增量。

**FR-16　体系导入导出与热更新**（优先级 P2）

- **输入**：体系 JSON 文件。
- **处理**：导出的 JSON 可供同学导入；导入生成新体系而非覆盖现有体系；体系变更通过全局信号通知分类引擎失效。
- **输出**：可分享的体系文件、导入后的体系树。
- **异常**：非法或损坏的 JSON 拒绝并提示；导入失败不改变现有体系；修改后无需重启，下一次分类即使用新规则。

### 5.3 模块 C：多特征融合双层分类与结果修正（FR-17—FR-22）

**FR-17　多模态预处理与四通道特征生成**（优先级 P0）

- **输入**：一条题目（题干、标注、附件、学科、题型）。
- **处理**：按题型分流到可插拔预处理单元：中文文本走清洗、jieba 分词（加载学科专有名词词典）、通用加学科双层停用词过滤、核心实词提取；英文走英文分词与词形还原（可选依赖缺失时退化为规则版后缀剥离）；公式走 LaTeX 到知识点的规则映射；图形走图中文字识别结果与人工标注；听力走转写文本。最终产出文本、公式、题型、学科四个通道的特征词。
- **输出**：预处理产物，含特征词、LaTeX、识别文本、转写文本与降级提示。
- **异常**：可选组件缺失时降级运行并把原因写入提示，界面"环境自检"逐项展示组件未安装、模型未准备、未验证、加载失败等状态；单个通道为空不影响整体分类。

**FR-18　第一层：关键词粗筛**（优先级 P0）

- **输入**：四通道特征词、当前体系的全部标签。
- **处理**：以倒排索引做关键词匹配，分词精确命中权重高于原文子串命中；人工修正学到的判别词以折扣权重并入索引并限制每标签数量；多字关键词按子词扩展并打折以补召回；按标签关键词数量做归一化，避免关键词多的标签通吃；一个关键词都未命中时按先验补齐候选下限，保证不漏；体系标签总数不超过上限时跳过粗筛。
- **输出**：3—5 个候选标签及其命中词。
- **异常**：候选全部来自兜底时，结果置信度折算到"建议复核"区间；体系内完全没有关键词时提示用户先配置。

**FR-19　第二层：多特征融合精匹配**（优先级 P0）

- **输入**：候选标签、四通道特征。
- **处理**：各通道计算 TF-IDF 余弦相似度，按分桶权重加权融合，空通道权重再分配后取最高分标签；得分低于阈值时标记"置信度偏低（建议复核）"；精匹配全为 0 但粗筛存在非兜底命中时采信粗筛结果并折算置信度，避免因词形不重叠把整题丢弃。
- **输出**：每个候选的通道得分与权重、最终标签、置信度。
- **异常**：候选全为兜底且得分为 0 时留空标签并提示补充关键词或样本；题目学科与所选体系学科不一致时提示更换体系。

**FR-20　分类依据展示**（优先级 P1）

- **输入**：一次分类的中间结果。
- **处理**：记录粗筛命中词、每个候选的四通道相似度与权重、提取到的特征词、识别出的 LaTeX、转写结果与耗时。
- **输出**：可展开的"分类结果与依据"面板，以及可按"置信度偏低"筛选的列表条件。
- **异常**：识别失败时在依据区显示失败原因，而不是留空白。

**FR-21　人工修正**（优先级 P0）

- **输入**：逐维度下拉选择的新标签，或"采纳为标准样本"操作。
- **处理**：修正后把本题判别特征按 IDF 加权并入正确标签画像、按比例衰减误判标签中的重合词、微调该"学科 × 题型"桶的通道权重、把学到的判别词以折扣权重并入粗筛索引，并将该维度标记为人工确认；重新分类全部时保留人工确认过的维度。
- **输出**：修正后的标签、反馈记录、落盘的学习数据。
- **异常**：把标签改回原值视为确认而非新信息，不注入特征，避免通用词在正确标签上反复堆积；题目内容修改后旧分类作废，需重新分类。

**FR-22　批量分类与任务控制**（优先级 P1）

- **输入**：未分类题目、选中题目或全部题目。
- **处理**：批量分类在后台线程执行，逐条记录结果；批量期间锁定编辑与其他数据任务；支持"只分类选中项"与"重新分类全部"。
- **输出**：进度提示、逐条结果、结束摘要。
- **异常**："停止任务"在当前文件或当前题处理完后生效，正在执行的识别步骤不能立即打断；批量期间关闭窗口会先请求停止，任务结束后需再次关闭。

### 5.4 模块 D：分类反馈与增量优化（FR-23—FR-24）

**FR-23　人工反馈的增量优化**（优先级 P0）

- **输入**：一次人工修正。
- **处理**：正强化按 IDF 分配并固定每次注入的总质量，负惩罚只衰减重合词且不下穿零；权重按感知机式规则只更新本题所在的"学科 × 题型"桶；向量空间自行维护词表、文档频率与文档数并做增量添加，不调用全量拟合；标签画像分基础层与增量层，基础层由体系重建且不持久化，增量层来自反馈且持久化。
- **输出**：更新后的画像、权重、粗筛索引与反馈记录。
- **异常**：修正只作用于当前体系与所在桶，不写全局；学习成果可整体回滚（重置权重规则或清空全部学习成果）。

**FR-24　学习过程可视化**（优先级 P2）

- **输入**：反馈日志与权重规则。
- **处理**：展示每次修正的时间、学科、题型、原判、改判与通道权重变化方向；展示各"学科 × 题型"桶的权重对比；修正率趋势曲线明确标注为代理指标，统计的是"被人工改过的比例"，不等同于准确率。
- **输出**：日志表、权重条形图、趋势图，均可导出为 Excel。
- **异常**：无记录时显示空状态引导；重置与清空操作需二次确认并说明影响范围。

### 5.5 模块 E：个性化导出、备份与恢复（FR-25—FR-29）

**FR-25　按体系隔离的 Excel 分 sheet 导出**（优先级 P0）

- **输入**：题目集合、当前体系、分 sheet 维度、是否只导出已分类题目。
- **处理**：按体系标识隔离当前体系的题目；生成"全部错题"总表、"分类统计"汇总表，以及每个标签一个独立 sheet；sheet 名做非法字符与长度上限处理并保证唯一；列宽按内容估算、冻结表头；附带图片、公式、音频的识别状态列。
- **输出**：`.xlsx` 文件，默认写入工作区导出目录。
- **异常**：文件被其他程序占用时提示先关闭；标签名含 `/ \ * ? : [ ]` 时自动安全化；未分类题目在导出前提示条数；旧工作区中缺少体系标识的历史记录保持兼容。

**FR-26　媒体分文件夹归档**（优先级 P0）

- **输入**：题目集合、归档维度。
- **处理**：按"维度 / 标签 /"两级文件夹复制图片与音频，生成带 BOM 的 `index.csv` 索引（保证 Excel 双击打开中文不乱码）；Windows 保留文件名加前缀规避。
- **输出**：带时间戳的媒体归档目录及索引文件。
- **异常**：附件缺失时跳过并在索引中标注；同名文件自动改名，不覆盖已有文件。

**FR-27　导出结构预览**（优先级 P2）

- **输入**：体系、维度、题目集合。
- **处理**：预估将生成的 sheet、每个 sheet 的题目数，并提示未分类条数与媒体缺失条数。
- **输出**：导出结构预览面板。
- **异常**：无题目时提示先导入；体系与题目学科不匹配时提示更换体系。

**FR-28　完整备份（ZIP）**（优先级 P0）

- **输入**：备份目标路径。
- **处理**：打包题目、体系、学习数据、设置、附件与历史导出；写入文件清单、文件大小与校验值，并校验主要数据字段类型与记录编号的唯一性。
- **输出**：单个 ZIP 备份文件。
- **异常**：附件缺失时阻止生成"看似成功"的备份；目标不可写或空间不足时明确报错；备份不包含运行环境、识别模型、日志与旧备份，需在文档中说明，避免用户误以为可整机还原。

**FR-29　从备份恢复**（优先级 P0）

- **输入**：本软件生成的备份 ZIP。
- **处理**：校验清单、文件大小、校验值、数据字段与路径安全（拒绝绝对路径、上级目录、未知目录、Windows 保留名），全部通过后先自动备份当前内容，再写入新数据并重定位附件；失败时尝试回滚。
- **输出**：恢复结果摘要与"恢复前备份"的位置。
- **异常**：任一校验失败都不替换当前数据；回滚也失败时给出恢复前备份与原数据暂存位置，提示保留现场；恢复后体系与学习数据立即生效。

## 6 非功能需求

**NFR-1　全流程离线运行**（P0）

- 需求描述：导入、预处理、识别、分类、修正、导出、备份的每个环节均在本地完成，运行期不调用任何云端接口，代码中不存在云端服务地址。
- 验收关注点：断网环境下走通 CASE 5 全流程；运行日志中不出现对外网络请求；首次安装依赖需要联网这一事实必须在用户文档中写明，不能与"离线运行"混为一谈。

**NFR-2　无需编程环境**（P0）

- 需求描述：发布形态为可直接运行的 Windows 程序，用户不需要安装 Python、不需要执行命令、不需要编辑配置文件；源码用户提供一键启动脚本。
- 验收关注点：双击启动即可进入主界面；界面内不出现需要用户输入命令的入口；环境准备步骤集中在启动脚本与识别组件安装脚本中。

**NFR-3　平台与运行环境**（P1）

- 需求描述：主环境为 Windows 11 与 Python 3.13.5；公式识别因兼容性运行在独立的 Python 3.12 环境（pix2tex 0.1.4 + torch 2.5.1 CPU）；界面基于 PyQt5。
- 验收关注点：在目标 Windows 版本上可启动并完成五页流程；公式组件作为独立进程运行，主程序不因公式组件异常而退出。macOS 属申报书规划内容，当前未提供经验证的发布包，本文按"未覆盖"记录，不在需求层面宣称已满足。

**NFR-4　轻量化与体积控制**（P1）

- 需求描述：默认安装不包含公式识别、语音转写等重依赖；构建脚本把 torch、paddle、whisper 等可选重依赖排除在默认打包范围之外，识别模型按需另行准备；界面图标使用内联矢量数据，不引入额外图片资源。
- 验收关注点：默认安装包可正常完成纯文本全流程；安装媒体识别组件前不出现因缺依赖导致的启动失败；模型体积在文档中如实给出（例如图片识别所用的本地模型在《用户使用手册》中记录为约 30.3 MiB），不使用"极小体积"这类无依据表述。

**NFR-5　响应时间与交互不卡顿**（P1）

- 需求描述：纯文本单条错题从导入到输出分类结果的目标耗时为 1 秒以内；批量分类、批量导入、预热等耗时操作放入后台线程；页面切换与列表刷新不得因数据量增长而明显阻塞；媒体识别属秒级长任务，必须显示进度、允许取消，并且不得冻结界面。
- 验收关注点：批量处理期间界面可响应停止操作；识别类任务有明确的进行中状态；耗时统计必须区分"文本分类耗时"与"含识别的全流程耗时"，不得用前者替代后者。

**NFR-6　数据安全与可恢复**（P0）

- 需求描述：所有用户数据存放于用户目录下的工作区，写入采用先写临时文件再原子替换的方式，异常退出不留下半个文件；备份包含清单与校验值，恢复前自动备份当前内容，校验失败不替换现有数据。
- 验收关注点：强制结束进程后工作区数据仍可读取；错误的备份文件不会破坏现有数据；备份与恢复的失败提示必须给出可执行的下一步，而不是只报"失败"。

**NFR-7　可扩展性**（P1）

- 需求描述：预处理层按可插拔单元组织，新增一种模态只需新增单元而不改调度代码；新增学科体系、维度、标签全部在界面完成；分类引擎按体系版本号失效重建，不需要重启进程。
- 验收关注点：新增单元不影响既有单元；新建体系保存后立即可用于分类；体系变更后旧特征库不会残留。

**NFR-8　可维护性与可测试性**（P1）

- 需求描述：界面层、核心层、模型与配置层单向依赖，核心层不导入 PyQt，保证核心逻辑可在无图形环境运行与测试；模块职责与目录结构在《开发文档》中说明。
- 验收关注点：核心模块可在无显示器环境导入并执行；新增功能有对应的自动化测试；测试与评测脚本可复现。

**NFR-9　易用性与可解释性**（P1）

- 需求描述：三栏布局（左侧导航、中间内容、右侧快捷操作），五个功能入口按"导入—体系—分类—反馈—导出"顺序排列；提供新手引导与深浅色主题；分类结果必须展示依据；环境状态必须集中可见。
- 验收关注点：首次使用者不阅读文档也能完成一次"导入—分类—导出"；分类依据区能回答"为什么判成这个标签"；缺少识别组件时用户能自行判断当前处于哪种状态。

**NFR-10　开源与可二次开发**（P2）

- 需求描述：源代码、内置学科体系与开发文档可一并交付，许可证与第三方组件许可单独说明；二次开发者可在不修改核心算法的前提下扩展学科库与预处理单元。
- 验收关注点：仓库内含许可证与依赖说明；文档说明构建与打包命令；公开范围（仓库、软著等）按实际成果单独确认，不以本地目录存在等同于已公开发布。

## 7 量化指标需求

### 7.1 指标来源与读法

本节指标全部引自申报书 4.4.1"分模块专项功能测试"与 4.2、4.4.2 相关表述。**本表只把申报书原文指标转写为可检查的需求条目，不构成本项目的合格判定，也不表示任何指标已经达成。** 实际测试数据、与指标的差距以及未完成项，统一见《功能测试报告》。

| 编号 | 指标对象 | 申报书原文指标 | 需求口径（可检查的判定对象） | 关联需求 |
|---|---|---|---|---|
| QI-01 | 纯文本核心特征提取准确率 | ≥95% | 对纯文本题干，清洗、分词、停用词过滤后提取的核心实词与人工认定的核心特征词一致的比例 | FR-17 |
| QI-02 | 分词错误率 | ≤3% | 在学科专有名词与术语语境下，被错误切分的词占参与统计词数的比例 | FR-17 |
| QI-03 | 公式特征提取准确率 | ≥90% | 公式图片或内联公式经识别与映射后，得到的知识点特征词与人工标注一致的比例 | FR-07、FR-17 |
| QI-04 | 图形题核心特征提取准确率 | ≥90% | 图形题经文字识别与人工标注融合后，提取的核心特征与人工标注一致的比例 | FR-06、FR-17 |
| QI-05 | 英语题核心特征提取准确率 | ≥90% | 听力与阅读类错题在转写、英文分词与特征提取后，核心特征与人工标注一致的比例 | FR-08、FR-17 |
| QI-06 | 纯文本错题分类准确率 | ≥95% | 纯文本题目最终分类标签与人工标注标签一致的比例 | FR-18、FR-19 |

| QI-10 | 人工标注样本规模 | 150 余条 | 覆盖纯文本、公式、图形、英语听力全类型并完成人工知识点标注的独立样本数量 | FR-14、第 9 章追踪表 |

### 7.2 指标口径说明

1. QI-01 至 QI-05 的评价对象是**特征提取**，不是最终分类结果；"识别有输出"不等于特征正确，公式与图形必须在真实图片上人工核对 LaTeX 与特征词。
2. QI-07 的分母应包含全部题型，且识别失败的样本不能从分母中剔除，否则会系统性高估准确率。
3. QI-08 的口径是"从导入到输出分类结果的全流程"，因此包含图片识别、公式识别与音频转写；不能用纯文本匹配的毫秒级耗时替代全流程耗时。
4. QI-09 必须在同类型、同口径下比较，并同时给出样本量与数据划分方式；样本量过小或划分敏感的提升不能作为结论。
5. QI-10 要求样本独立于内置关键词库与规则调试过程；与关键词库同源的样本只能用于回归，不能替代独立评测集。

### 7.3 对项目主验收记录的说明

在 155 条人工标注样本上，项目主验收记录为：知识点分类准确率 98.1%，纯文本分类准确率 98.8%，粗筛召回 100%。该批样本与内置关键词库、规则调试过程同源，项目文档已明确其"不代表独立泛化能力"，因此本节不将其作为 QI-01 至 QI-10 任何一项的达标结论。媒体识别耗时与反馈提升的实测差异同样记录在《功能测试报告》，本文不重复判定。

## 8 需求优先级与范围边界

### 8.1 优先级定义

| 级别 | 含义 | 判定标准 |
|---|---|---|
| P0 | 必须实现 | 缺失则申报书四大核心模块或五页主流程无法走通，或用户数据存在丢失风险 |
| P1 | 重要 | 不影响主流程走通，但直接影响结果可信度、数据安全或可解释性 |
| P2 | 增强 | 提升体验与可分享性，缺失时可用替代方式完成同一目标 |

### 8.2 优先级分布

| 模块 | P0 | P1 | P2 | 小结 |
|---|---|---|---|---|
| A 导入与预览 | FR-01、FR-02、FR-03 | FR-04 至 FR-09 | — | 入口必须覆盖文本、表格、图像、音频四类来源 |
| B 分类体系管理 | FR-10 至 FR-13 | FR-14、FR-15 | FR-16 | 自建体系是 P-3 的直接对策，关键词与标签为 P0 |
| C 分类与修正 | FR-17 至 FR-19、FR-21 | FR-20、FR-22 | — | 双层分类与人工修正是核心链路 |
| D 反馈优化 | FR-23 | — | FR-24 | 增量机制优先，可视化属于体验层 |
| E 导出与备份 | FR-25、FR-26、FR-28、FR-29 | — | FR-27 | 导出是交付价值出口，备份是数据保全底线 |

合计：P0 共 16 条，P1 共 10 条，P2 共 3 条。所有 P0 需求均有对应的实现位置（见第 9 章），没有只存在于文档中的 P0 需求。

#### 8.2.1 优先级判定中的两点取舍

- **备份与恢复定为 P0 而非 P2**：系统没有账号与云端，备份是唯一的迁移与恢复手段，一旦缺失，用户换机即等于数据不可带走。这一条在申报书五大模块中未单列，属于实现阶段根据"个人离线工具"定位补充的需求。
- **反馈可视化定为 P2**：分类准确率的提升依赖增量机制本身（FR-23），可视化只是让过程可观察；即使没有图表，机制仍然工作，因此不作为结题硬性条件。

### 8.3 明确的范围外内容

以下内容不在本系统 1.0.0 的需求范围内，不作为缺陷或未完成项处理。

| 范围外项 | 具体含义 | 原因与替代方式 |
|---|---|---|
| 通用图形语义理解 | 识别图中的几何关系、电路拓扑、受力方向、坐标轴含义等"图意" | 当前只提取图中文字与参数并结合人工标注；通用图形关系理解不在能力范围，申报书对应要求也是"OCR 提取 + 用户补充标注" |
| 手写识别 | 对手写体题干、手写公式、手写批注的识别 | 图片文字识别面向印刷文字；手写内容由用户直接录入题干或写入标注 |
| 自动解题与答案生成 | 给出题目答案、解题步骤或知识点讲解 | 系统只做分类与归档，不做求解；避免把"分类工具"扩张为"学习机" |
| 账号体系与云同步 | 注册登录、多端同步、云端存储 | 与离线、免费、隐私不外传的定位冲突；换机迁移由备份恢复承担 |
| 移动端应用 | iOS/Android 客户端或小程序 | 界面基于 PyQt5 桌面技术栈，无移动端实现；申报书交付形态为桌面程序 |
| 题库检索与搜题 | 联网检索原题、匹配标准答案、按题目搜索题库 | 大学生课后习题与院校自命题多不在公开题库中，且需联网；系统改为按自建体系分类 |
| 多人协作与班级管理 | 教师端后台、班级成员管理、成绩统计看板 | 单机单用户定位；共享方式是体系 JSON 的导出与导入 |
| macOS 与低配设备验收 | macOS 原生包、指定低配机型的实机验收 | 申报书列为规划；当前发布与验证以 Windows 为主，未覆盖部分在测试报告中如实披露，不在需求层面宣称满足 |

### 8.4 边界内的克制原则

范围边界不只是"不做什么"，也包括"做但不扩张"：

- 不因为支持多维度就内置大量预置维度，内置维度保持知识点、错因、难度、优先级四项，其余交给用户自建；
- 不因为能识别媒体就引入视频、PDF 版面还原、Word 排版等新模态；
- 不因为能导出的内容多就默认全量导出，导出维度与范围由用户明确选择，并在预览中确认。
