## 1. 分层架构

```
main.py
  └─ app/ui/main_window.py         三栏布局，QStackedWidget 承载五个功能页
       ├─ app/ui/context.py        AppContext：跨页共享状态 + 信号总线
       └─ app/ui/pages/*.py        五个功能页，各自只依赖 AppContext
              ↓
       app/core/dataio/            导入 / 导出
       app/core/classify/          双层分级分类 + 增量优化
       app/core/preprocess/        多模态预处理（可插拔单元）
       app/core/storage.py         仓库层（原子写）
       app/core/models.py          数据模型（纯 dataclass，无框架依赖）
       app/config.py               路径 / 常量 / 算法参数
```

**依赖方向严格单向**：`ui → core → models/config`。`core` 里不出现任何 PyQt 导入，因此全部核心逻辑都能在无图形环境下测试（CI 里就是这么跑的）。

页面之间不互相持有引用，全部通过 `AppContext` 的信号通信：

| 信号 | 谁发 | 谁收 |
|---|---|---|
| `questions_changed` | 导入/分类/删除 | 所有列表页刷新 |
| `scheme_changed` | 体系编辑 | 引擎特征库失效 + 各页下拉框刷新 |
| `feedback_changed` | 人工修正 | 反馈页刷新 |
| `toast` / `status` | 任意页 | 主窗口浮层 / 状态栏 |

## 2. 数据模型

`app/core/models.py`，全部是纯 `dataclass` + `to_dict/from_dict`，不依赖任何框架。

```
Scheme（分类体系）
 └── Dimension（分类维度：知识点 / 错误类型 / 难度 / 优先级 / 自定义）
      └── CategoryLabel（分类标签）
           ├── keywords: List[str]        第一层粗筛依据
           ├── samples: List[str]         第二层精匹配的标签画像来源
           └── weight_override: Dict      标签级权重覆盖（可选）

Question（错题）
 ├── raw_text / annotation / media_path
 ├── subject / qtype                      自动推断，用户可改
 ├── labels / label_names / scores        各维度的分类结果
 ├── corrected: Dict[str, bool]           哪些维度被人工确认过
 └── feature: Dict                        预处理产物快照（供界面展示依据）

FeatureBundle（预处理产物）
 ├── text_tokens / formula_tokens         两个主特征通道
 ├── qtype_tokens / subject_tokens        两个辅助特征通道
 ├── latex / ocr_text / transcript        各识别引擎的原始产出
 └── notes: List[str]                     降级提示（"未安装 pix2tex"之类）
```

`Scheme.revision` 是个单调递增的版本号，`touch()` 时 +1。分类引擎缓存 `_revision`，不一致就重建特征库——这就是"改完立即生效，不用重启"的实现方式。

## 3. 多模态预处理层

### 可插拔单元

`preprocess/base.py` 维护一个单元注册表，每个单元声明自己能处理什么：

```python
@register
class FormulaUnit(PreprocessUnit):
    name = "formula"
    def accepts(self, q) -> bool: ...
    def process(self, q, fb) -> None: ...
```

`pipeline.preprocess()` 只负责调度。加一种新模态（比如手写体识别）只要写一个新单元，不用改调度代码。

### 各单元

| 单元 | 依赖 | 缺依赖时的降级行为 |
|---|---|---|
| `text_cn` | jieba（必需） | — |
| `text_en` | NLTK（可选） | 退化为规则版后缀剥离 |
| `formula` | pix2tex（可选） | 仍能处理题干内联的 `$...$` 公式 |
| `figure` | PaddleOCR（可选） | 仅用人工标注 |
| `audio` | faster-whisper / whisper（可选） | 仅用人工标注 |

**所有可选依赖都是 try-import + 标志位**，`pipeline.engine_report()` 返回每个引擎的可用性与人话解释，界面「环境自检」直接渲染它。这不是可有可无的礼貌——用户必须知道自己现在处于哪种状态，否则"识别不出来"会变成一个无从排查的谜。

### 公式-知识点映射词典

**这是本项目最核心的创新点。**

问题：LaTeX 不能直接分词。`\int_{0}^{1} x\,\mathrm{d}x` 切碎了得到 `int`、`0`、`1`、`x`、`mathrm`、`d`——毫无意义，而且不同知识点的公式切出来的碎片高度雷同。

做法：用正则把**公式的结构特征**映射成**知识点特征词**。`tools/build_formula_map.py` 生成 `resources/formula_map.json`，当前 **85 条**规则：

```json
{
  "subject": "高等数学",
  "pattern": "\\\\int_\\s*\\{?[^}\\s]*\\}?\\s*\\^",
  "tokens": ["定积分", "牛顿莱布尼茨公式"],
  "weight": 2.5,
  "note": "带上下限的积分"
}
```

三个设计点：

1. **规则顺序敏感**：带上下限的 `\int` 必须先于裸 `\int` 匹配，否则定积分会被误判成不定积分。生成器保证了顺序。
2. **学科隔离**：`subject` 字段限定规则的适用范围（`"*"` 表示全学科）。`E=mc^2` 在物理题里映射成"质能方程"，在高数题里不该产生任何特征（有测试锁死）。
3. **weight 用重复注入实现**：`weight: 2.5` 就是把 token 重复 `round(2.5)` 次塞进 `formula_tokens`，让它在 TF-IDF 里自然拿到更高词频。不需要给向量空间加特殊的加权逻辑。

### 分词

- **专有名词词典**（`resources/userdict/*.txt`）：不加的话"洛必达法则"会被 jieba 切成"洛必达"+"法则"，关键词永远匹配不上。这是中文技术文本分类的头号坑。
- **双层停用词**：通用停用词（的/是/在）+ 学科通用词（如图/所示/下列/说法/正确）。后者是关键——"如图所示"在物理题里出现率极高但零判别力。

## 4. 双层分级分类层

### 第一层：关键词粗筛（`coarse.py`）

倒排索引 `词 -> [(label_id, weight)]`，外加三个机制：

- **子词扩展**：用 `jieba.cut_for_search` 把多字关键词拆成子词也建索引，权重打 `SUBWORD_DISCOUNT=0.35` 的折扣。这让"干涉条纹"能召回"光的干涉与衍射"。折扣保证它只补召回，不足以让弱相关标签挤掉强相关标签。
- **长度归一化**：`norm[label] = sqrt(关键词数 + 1)`，避免关键词多的"大标签"通吃。
- **召回兜底**：一个关键词都没命中时，按先验补齐到 `COARSE_MIN_K=3` 个候选。宁可多算，不可漏掉——粗筛漏了，精匹配再准也没机会。

标签数 ≤ top_k 时直接跳过粗筛（`direct=True`），因为此时粗筛没有任何收益。

### 第二层：多特征融合精匹配（`fine.py`）

四个特征通道，各自算 TF-IDF 余弦相似度，再加权融合：

| 通道 | 内容 |
|---|---|
| `text` | 题干 + 标注 + OCR + 转写的分词结果 |
| `formula` | 公式映射出的知识点特征词 |
| `qtype` | 题型特征词 |
| `subject` | 学科特征词 |

权重按 `(学科, 题型)` 分桶（`weights.py` 的 `DEFAULT_RULES`）：

```python
(高等数学, 公式类):  {文本 0.35, 公式 0.45, 题型 0.10, 学科 0.10}
(大学英语, 听力):    {文本 0.60, 公式 0.02, 题型 0.28, 学科 0.10}
```

**空通道权重再分配**（`redistribute`）：某条题压根没有公式特征时，把公式通道的权重按比例摊给其余通道，而不是白白扣掉。否则纯文本题的置信度会被系统性拉低，"置信度偏低"的提示就没法用了。

### 增量 TF-IDF（`vector_space.py`）

需求硬性要求"无需全量重训"，所以没有用 `TfidfVectorizer.fit()`——那是全量重扫语料。这里自己维护：

```python
vocab: Dict[str, int]     # 词 -> 列号
df: List[int]             # 每个词的文档频率
n_docs: int
```

`add_document(tokens)` 是 O(本题词数)。`idf()` 与 sklearn 的 `smooth_idf=True` 逐位一致：

```
idf(t) = log((1 + n_docs) / (1 + df(t))) + 1
```

`tests/test_classify.py::TestVectorSpace::test_idf_formula_matches_sklearn` 用真实的 `TfidfVectorizer` 逐词比对，锁死这一点——不然"基于经典 TF-IDF 方法"就是句空话。

### 标签画像 base + delta 双层（`LabelProfile`）

```
effective_tf = clip(base_tf + delta_tf, 0)
```

- `base_tf`：由分类体系（关键词 + 标准样本）重建，**不持久化**
- `delta_tf`：来自人工反馈，**持久化**

为什么只存 delta：base 是用户手改关键词的产物，持久化它会和用户的编辑打架——用户删掉一个关键词，结果它还在画像里阴魂不散。

## 5. 人工反馈增量优化

一次 `apply_correction` 做四件事，全部是 O(本题词数) 或 O(1)：

1. **正强化**：把本题的判别特征按 IDF 加权并入正确标签的 `delta_tf`，每次注入的**总质量固定**
2. **负惩罚**：把误判标签里与本题重合的词按比例衰减（不下穿 0）
3. **权重在线更新**：感知机式 `Δw = lr · (右通道得分 − 错通道得分)`，只改这一个 `(学科, 题型)` 桶
4. **反哺粗筛**：把学到的 top-N 判别词并入粗筛倒排索引（权重打折 `COARSE_LEARNED_WEIGHT=0.55`）

第 4 步是后来补的，因为发现真正的瓶颈在第一层：冷启动时粗筛召回只有 91%，正确标签根本进不了候选集，精匹配再准也翻不了盘。反馈只更新精匹配等于隔靴搔痒。

**关于效果，请读 README「已知局限」第 1 条**——需求要求的 ≥5pp 提升实测做不到（同类型口径 +3.4pp，且落在噪声内）。文档里写清楚了实验设计、数据和原因，没有粉饰。已经锁死的性质是**修正不会让准确率倒退**。

## 6. 界面层

- **三栏布局**：左导航（`NavBar`）+ 中内容（`QStackedWidget`）+ 右快捷操作（`QuickActionPanel`）
- 每个页面继承 `BasePage`，实现 `quick_actions()` 返回右侧要显示什么、`on_show()` 在被切到时刷新
- **主题**：`theme.py` 集中管理配色与 QSS，页面代码里不出现硬编码颜色
- **图标**：`icons.py` 内联 SVG 路径数据，随主题动态着色。不需要外部图片资源，打包更简单
- **新手引导**：`guide.py` 半透明遮罩 + 对目标控件"挖孔"高亮 + 分步气泡
- **后台线程**：`workers.py` 把预热、批量导入、批量分类放进 QThread，保证界面不卡

耗时操作（OCR、音频转写）动辄数百毫秒到数秒，放主线程会直接冻住界面。批量分类时单条失败不影响整批——记录下来继续跑，最后一起报告。

## 7. 关键设计决策

| 决策 | 理由 |
|---|---|
| 手写增量 TF-IDF 而非 `TfidfVectorizer` | 需求要求"无需全量重训"，`fit()` 是全量重扫 |
| 画像 base/delta 双层，只持久化 delta | 避免与用户手改关键词冲突 |
| 重依赖全部可选 + 优雅降级 | 学生装不上 1.5GB 的 PyTorch 就用不了，这不可接受 |
| 权重更新只改具体 `(学科,题型)` 桶 | 改通配桶会让一次修正污染全局 |
| 粗筛子词扩展打折而非等权 | 只补召回，不该让弱相关标签挤掉强相关的 |
| 工作区放用户主目录 | 打包后安装目录通常只读，写进去会失败 |
| JSON 原子写（tmp + `os.replace`） | 断电 / 强杀不会留下半个文件 |
| 图标用内联 SVG | 打包无需额外资源，换主题自动跟着变色 |
| `core` 层零 PyQt 依赖 | 核心逻辑可在无图形环境测试 |

## 8. 踩过的坑

这一节记录开发中实际发现并修掉的 bug，都是有代价的教训。

### 次线性词频对小数词频产生负权重

```python
# 错误
return 1.0 + math.log(count)
```

`1 + log(c)` 只在 `c >= 1` 时有意义。但 delta 层经过增益与衰减后会累积出小数：`1 + log(0.2) = -0.61`，**负权重**。后果是被负反馈衰减过的词不是"变弱"，而是**反向排斥**含该词的题目——负反馈的语义整个翻转。

这个 bug 隐蔽得很：它让增益扫描出现反常的非单调（gain=0.1 反而比 gain=1.0 差 6 个百分点），才暴露出来。

```python
# 正确：只在 c>1 时做对数压缩，c<=1 时退化为线性
return 1.0 + math.log(count) if count > 1.0 else count
```

两段在 `c=1` 处连续、全程单调不减且非负；对整数词频与 sklearn 完全一致。

### 评测脚本的实验之间互相污染

`tools/evaluate.py` 原先在同一个进程里依次跑各实验。它们会互相污染进程内的全局状态（jieba 词典、引擎缓存的词表 df、`WeightRules` 的落盘文件），**导致后跑的实验拿到被前面改过的起点**。

后果很严重：增量优化实验的冷启动基线被从 74.4% 压到 67.9%，**凭空多算出 6 个百分点的"提升"**，一度让人以为达标了。同进程跑出来的数字依赖执行顺序、不可复现，没资格进结题报告。

现在每个实验派生独立子进程（`--only` 参数），跑两遍数字完全一致。

### 正强化淹没关键词库

原先 `reinforce` 把题干的每个词都加 1.0。冷启动时标签的基础画像只有两三个关键词（质量 ~4），一条题干十几个词各加 1.0 —— **一次修正就让噪声质量压过人工关键词 4 倍**，L2 归一化后关键词的贡献被稀释殆尽。而且通用词（求/计算/判断）会在所有标签画像里同步堆积，把画像互相拉近。

改成 **按 IDF 分配 + 每次注入的总质量固定**：通用词几乎分不到质量，长题干也不会天然比短题干更有话语权。

### `apply_correction` 违反自己的文档契约

文档写着"标签未变则返回 None"，代码却照样往画像里灌一遍词。用户把下拉框选回原值只是**确认**，不是新信息；照灌会让题干里的通用词在已经正确的标签上反复堆积。在冷启动实验里，77 次"修正"有 57 次是这种无效确认。

### 标签级权重覆盖退回全局兜底规则

```python
# 错误：merged 的底座是 ("*","*")
merged = dict(DEFAULT_RULES[("*", "*")])
merged.update(override)
```

用户只想把某个标签的公式权重拉高，结果其余通道**悄悄退回了通用规则**（文本 0.70…），而不是该学科·题型该有的比例（高数公式题 文本 0.35 / 公式 0.45），同时还**丢弃了系统已从反馈中学到的权重**。

现在 override 的语义明确为"在本桶权重之上打补丁"。

### 新手引导 mapTo 段错误（最严重的一个）

```python
tl = w.mapTo(self, QPoint(0, 0))    # self 是遮罩层，不是 w 的祖先 -> SIGSEGV
```

Qt 的 `mapTo(parent, pos)` **要求 parent 是调用控件的祖先**。引导遮罩层是主窗口的
子控件，跟导航按钮是叔侄关系——传非祖先属于未定义行为，实测直接 SIGSEGV，整个进程没了。

严重性：新手引导在**每个新用户首次启动时自动触发**，等于打开就崩。之所以一直没
发现，是因为所有端到端测试都设了 `guide_done=True` 跳过引导——**测试跳过的路径，
恰恰是新用户唯一会走的路径**。

修法：`self.mapFromGlobal(w.mapToGlobal(QPoint(0,0)))`，全局坐标不依赖控件树层级。

### 把关键词注入 jieba 全局词典

同步分类体系时曾把全部关键词以 `freq=2000` 注入 jieba。jieba 的词典是**进程级
全局**的，于是：

- 关键词互相污染：一条「分词作状语」把"现在分词和过去分词作状语"从
  `现在分词/过去分词/状语` 变成 `现在分词/分词作状语`——"过去分词"被吃掉了
- 跨学科污染：物理的关键词会改变英语题的分词
- **不可复现**：同一道题的结果依赖"你之前打开过哪套体系"

原注释说"否则粗筛永远命中不了"是错的——粗筛有三重兜底。实测注入只换来 +0.6pp
（1 条题），却把英语特征提取从 93.3% 压到 86.7%。已移除并封死。

### 精匹配为 0 时把题丢着不分

题干"水平渐近线" vs 关键词"渐近线"：粗筛子串命中并排第一，精匹配按分词算余弦→
词形零重叠→0 分→引擎判空标签。整题被丢掉。修法：精匹配全 0 但粗筛有非兜底命中时
采信粗筛，置信度折算到"建议复核"区间。

### 其他

- **Excel sheet 名非法字符**：`/ \ * ? : [ ]` 和 31 字符上限。标签名叫"阅读/完形"是很自然的写法，不处理会导出到一半抛异常。
- **Windows 保留文件名**：`CON` / `PRN` / `NUL` / `COM1`…，建同名文件夹会直接失败。
- **`index.csv` 必须带 BOM**：不带的话 Excel 双击打开中文全是乱码。
- **GBK 编码**：Windows 记事本默认存 GBK，识别不了等于用不了。兜底链是 `utf-8-sig → utf-8 → gbk → gb18030 → big5 → utf-16`。
- **QtMultimedia 可能缺失**：精简系统缺 libpulse 时 import 就炸。做成 try-import + 标志位，降级为"用系统播放器打开"。

## 10. 打包

```bash
python tools/build.py              # 单文件
python tools/build.py --onedir     # 目录模式（启动快、便于排查）
python tools/build.py --spec-only  # 只生成 spec
```

`tools/build.py` 会生成 `.spec` 再调 PyInstaller。要点：

- `datas` 带上 `resources/` 与 `samples/`；`config._base_dir()` 在冻结环境下指向 `sys._MEIPASS`
- `hiddenimports` 补上 jieba / sklearn / scipy 的动态导入（静态分析扫不到）
- `excludes` 排除可选重依赖（torch / paddle / whisper），否则包体积上 GB

PyInstaller **不支持交叉编译**：Windows 的 exe 要在 Windows 上打，Mac 的 app 要在 Mac 上打。两边命令一样。

## 可以往下做的方向

1. **样本量**：目前 155 条是最大的短板，直接导致增量优化的效果测不准。要验证"提升 ≥5%"至少需要再大一个数量级的独立标注数据。
2. **独立盲测集**：现有评测集与关键词库同源，属于闭卷自测。找外部真题重测才知道真实泛化能力。
3. **对比基线**：可以加朴素贝叶斯、SVM 作为对照组，让"传统方法"的选型更有说服力。
4. **反馈算法**：当前是"IDF 加权注入 + 感知机式权重更新"。样本量上来后可以试试更强的在线学习方法（如 Passive-Aggressive），但要守住"O(本题词数)、无需重训"这条线。
